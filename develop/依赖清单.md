# 第三方依赖清单

本文件登记 GIme 里**直接打包进 APK 的第三方前端代码**。每并入一份都要能回答三个问题：
它是谁、许可怎么算、本地这份到底是哪一版（可复算的指纹）。

原生侧的依赖（pdfbox-android、cronet-bundled）由 `app/build.gradle.kts` 管，走 Gradle 的
正常解析与校验，不在此重复登记。

| OpenUI Lang 核心解析器 | `@openuidev/lang-core` | `1.0.2` | MIT | `app/src/main/assets/ui/openui-core.js` | 532957 |
| OpenUI 宿主适配层 | 本项目自写（源自 `agent` 仓库） | — | 随本项目 | `app/src/main/assets/ui/openui-ui.js` | 10048 |

`openui-core.js` 不再是 agent 仓库的原样产物：它由 `tools/openui-bundle/` 用
`@openuidev/lang-core@1.0.2` + `zod@4.6.7` + esbuild（target=chrome80）重新打包，
修掉了旧 bundle 里 `OpenUI.prompt()` 走废弃 `generatePrompt` 导致组件签名全是 `undefined` 的问题。

`openui-ui.js` 不是第三方包：它是把 `@openuidev/lang-core` 的解析结果画成 DOM 的那一层，
并入时只做了少量宿主适配（见 §4）。

## 4. 我们对上游做的改动

`openui-core.js` 由 `tools/openui-bundle/` 重打（入口 `entry.mjs` 按上游 `createLibrary` /
`defineComponent` 定义 15 个组件，导出 `parse/stream/prompt/schema/signatures`）；
`openui-ui.js` 是自写渲染层，共三处宿主适配：

1. 去掉两处 `export ` 前缀—— GIme 用 classic script 加载，不能有 ESM 语法。
2. 文件尾加出口：
   ```js
   window.renderOpenUI = renderOpenUI;
   window.readForm = readForm;
   ```
3. `renderOpenUI` 读取 `res.meta.errors`：解析器丢弃非法节点时追加 `.oui-warn`
   提示（「卡片有 N 处格式问题」），不再静默留空卡。

除此之外逻辑、注释、函数体与原适配层一致。

CSS 侧：`agent` 仓库 `public/style.css` 里的 OpenUI 组件规则（`.oui*` 36 块 + `.pick-*` 6 块 +
令牌桥接 2 块）原样摘出，追加到 `app/src/main/assets/style.css` 末尾
（`/* ==== OpenUI ==== */` 段）。唯一改动是把 6 处 flex `gap` 换成相邻兄弟 `margin`：

| 选择器 | 原 | 现 |
|---|---|---|
| `.oui-stack` | `gap: 10px` | `.oui-stack > * + * { margin-top: 10px; }` |
| `.oui-row` | `gap: 8px` | `.oui-row { margin: -4px; }` + `.oui-row > * { margin: 4px; }` |
| `.oui-progress` | `gap: 6px` | `.oui-progress > * + * { margin-top: 6px; }` |
| `.oui-field` | `gap: 4px` | `.oui-field > * + * { margin-top: 4px; }` |
| `.oui-toggle` | `gap: 8px` | `.oui-toggle > * + * { margin-left: 8px; }` |
| `.oui-form` | `gap: 10px` | `.oui-form > * + * { margin-top: 10px; }` |

原因：设备 WebView 实测是 **Chromium 80.0.3987.132**（`adb shell dumpsys webviewupdate`），
flex `gap` 要 Chrome 84+，在 80 上整条声明会被丢弃，卡片内元素会全贴在一起。

另注：GIme 自己的 `style.css` 里也有大量 `gap:`（`.cats`、`.chat-head`、`.conv-row`、`.msg` 等），
在本机 80 内核上同样不生效。这是**并入前就存在的既有问题**，不是 OpenUI 引入的，本次未动。

## 5. 运行期网络行为

### 5.1 结论：不联网

`openui-core.js` 内唯一的 URL 字面量清单（穷举）：

| URL | 用途 |
|---|---|
| `http://json-schema.org/draft-04/schema#` | JSON Schema 元数据标识 |
| `http://json-schema.org/draft-07/schema#` | 同上 |
| `https://json-schema.org/draft/2020-12/schema` | 同上 |
| `https://zod.dev/v4/versioning` | zod 4 报错提示文案 |
| `https://example.com` | 文档/示例字符串 |
| `https://dgoeivjus9jfp.cloudfront.net` | **遥测上报域名（见下）** |
| `http://[${e}]` | IPv6 模板串 |

无 `sourceMappingURL`，无外部 CDN、无字体、无图片、无动态 `fetch` 到第三方。

### 5.2 遥测：默认关闭

bundle 仍保留上游的 PostHog 上报代码（host `https://dgoeivjus9jfp.cloudfront.net`），
事件为 `lang_core_parser_parse_used`、`lang_core_system_prompt_generation_used`。

门控逻辑：`OPENUI_RUNTIME_TELEMETRY_ENABLED` 未显式置为真时不启用；
即使启用也只采 1/10。WebView 里没有这个环境变量 → 一个请求都不发。

本轮以 `@openuidev/lang-core@1.0.2` 官方包重打，未修改这段门控。

上报字段本身是 `component_count` / `tool_count` / hash 之类的聚合元数据，
不含 prompt 正文、不含组件内容、不含用户输入。

**纵深防御建议**：日后若加 `shouldInterceptRequest`，可对该 cloudfront 域名加一条黑名单，
成本几乎为零。P0 未加（当前代码里根本没有 `shouldInterceptRequest`）。

## 6. 接线契约（改这里的人必读）

### 6.1 加载顺序（`index.html`）

```html
<script src="bank.js"></script>
<script src="ui/openui-core.js"></script>   <!-- 必须在前：挂 window.OpenUI -->
<script src="ui/openui-ui.js"></script>     <!-- 依赖 window.OpenUI，出口 window.renderOpenUI -->
<script src="app-core.js"></script>
<script src="app-admin.js"></script>
<script src="app-chat.js"></script>
```

`ui/openui-*.js` 必须在 `app-chat.js` 之前就位：气泡渲染要调 `window.renderOpenUI`。
顺序的权威定义在 `tools/check.mjs` 的 `JS_FILES` 常量，改加载顺序要一起改。

### 6.2 用到的出口

| 出口 | 使用方 | 用途 |
|---|---|---|
| `parse` | `openui-ui.js` | 把卡片源码解析成元素树 |
| `signatures` | `app-chat.js` `ouiSignatureLines()` | 把 15 个组件的官方签名拼进系统提示 |
| `prompt` | 测试/工具 | 上游完整生成提示（含正确签名），App 只取签名段 |
| `schema` | 兜底 | 老 bundle 没有 `signatures` 时从 `$defs` 拼签名 |
| `stream` | 暂未使用 | 保留给未来的流式渲染 |

**不能**把 bundle 裁到只剩 `parse`：`signatures` 与 `parse` 共用同一个 library/schema，硬删会碎。

### 6.3 渲染入口

| 位置 | 作用 |
|---|---|
| `app-chat.js` `ouiSplit(m)` | 抽出 ```openui-lang 围栏，返回 `{text, src}` |
| `app-chat.js` `stripUIFence(s)` | 流式期把没收尾的围栏藏住，防源码闪一下 |
| `app-chat.js` `mdFor(m)` | 正文走 `mdToHtml(ouiSplit(m).text)`，源码不进气泡 |
| `app-chat.js` `chatOuiMount(root)` | `innerHTML` 落地后按 `[data-oui]` 挂真 DOM（字符串里塞不了节点） |
| `app-chat.js` `chatOuiAction(...)` | 把动作摊成通用载荷，交 `window.onOuiAction` |
| `window.onOuiAction(action, payload)` | P0 只回传到 `Android.ouiAction` 打 logcat，不猜业务语义 |

动作路由（`send:` / `submit:` 真正发消息、`nav:` 跳转）留到 P1。
`openui-ui.js` 的 `renderOpenUI(source, opts)` 返回**真实 DOM 元素**，不是字符串。

## 8. 升级指引

要换 `@openuidev/lang-core` 版本，**不要在 GIme 里手改产物**：

1. 改 `tools/openui-bundle/package.json` 的钉版；
2. `cd tools/openui-bundle && npm install && npm run build`；
3. 重算 §2 的指纹并更新本文件；
4. 跑 `tools\check.mjs`（`[30b] OpenUI 卡片渲染` 段会验 `parse` 与 `signatures`）；
5. 真机冒烟：让大肥鱼输出一张 ```openui-lang 卡片，看它渲染成真组件而不是源码；
   再在 CDP 里核对 `OpenUI.prompt()` 不含 `undefined —`。
