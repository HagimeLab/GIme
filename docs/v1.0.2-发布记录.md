## 为什么单独发一版

v1.0.1 已发布，且「检查更新」只读 `releases/latest`。
如果沿用 1.0.1 覆盖同名 tag，已安装 1.0.1 的用户版本号相同，
`Ver.isNewer` 会判定「无新版本」，永远收不到这次的下载修复。
所以必须提升 versionCode/versionName，让老用户能正常收到更新。

## 本次修的问题

真机复现（M600 Pro，v1.0.0 → v1.0.1）：

- `DownloadManager` 连 `github.com:443` 超时（`failed to connect ... after 20000ms`），
  随后进入 `WAITING_TO_RETRY(194)` 并无限重试；
- 原 `poll()` 只处理 RUNNING/FAILED/SUCCESSFUL，194 落到末尾 `return true`，
  被当成「还在下载」→ 界面永远停在 0%，无任何提示。

修复：

1. `DownloadOutcome` 把 194 / PAUSED / FAILED 一律判为失败（纯类，可桌面测试）。
2. `poll()` 增加「25 秒无字节增长即判卡死」。
3. 下载前先做连通性预检（HEAD、不跟随重定向、6 秒超时），连不上直接给结论。
4. 失败弹窗新增「打开发布页」，绕开被屏蔽的下载域名。
5. 修掉 `onUpdateChecking → onUpdateDownloading` 切换时标题卡在「连接中」。
