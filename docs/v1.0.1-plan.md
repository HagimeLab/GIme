> 版本定位：在保持现有 Android + Java + WebView + 本地存储架构的前提下，优先修复影响发布安全、考试流程、题库导入和数据一致性的确定性问题，并完善应用内更新弹窗的更新日志展示。
>
> 版本性质：维护型小版本。此版本不进行大规模重构，不引入大型前端框架，不改变现有主要操作习惯。

## 1. 版本目标

v1.0.1 聚焦四个目标：

1. **修复关键流程问题**：确保模拟考试交卷、退出、计时和最后一题切换行为一致。
2. **提升导入可靠性**：避免冷启动时外部文件导入早于页面初始化，并明确提示不支持的文件格式。
3. **保护数据与发布安全**：关闭 Release WebView 调试，改进题库文件保存/删除的一致性，避免源码交付包暴露签名材料。
4. **改善版本更新体验**：检测到新版本后，在现有更新弹窗中显示版本信息和更新日志，用户可阅读后再决定是否更新。

### 本版本不做的事

- 不重写现有 Java + WebView 架构。
- 不新增云端账号、云同步或服务端题库。
- 不重构全部题库数据，也不在没有依据时批量修改答案。
- 不在本版本一次性实现间隔重复、知识点图谱或每日学习计划。
- 不强制更换已用于发布的签名密钥；签名迁移必须单独评估覆盖安装兼容性。

## 3. 详细功能与修复设计

### 3.1 更新弹窗增加更新日志

#### 用户体验目标

用户点击“检查更新”后：

- 没有新版本：显示“当前已是最新版本”及当前版本号。
- 有新版本：展示新版本号、发布日期（如果更新源提供）、简短更新说明和完整更新日志。
- 更新日志显示在现有新版本弹窗的下方，不替换现有弹窗和更新按钮。
- 更新日志较长时，内容区域可滚动；弹窗底部的“立即更新”和“稍后”操作应保持可见。
- 更新信息加载失败时，仍能显示版本和更新操作；日志区显示“暂时无法获取更新日志”，不能让整个更新流程失效。
- 用户选择“稍后”只关闭弹窗，不下载、不安装。
- 用户选择“立即更新”后，继续使用现有下载和系统安装流程。

#### 推荐弹窗布局

```text
┌──────────────────────────────────────┐
│              发现新版本               │
│                                      │
│  当前版本  v1.0.0                     │
│  最新版本  v1.0.1                     │
│  发布日期  2026-XX-XX（可选）         │
│                                      │
│  更新日志                             │
│  ──────────────────────────────────  │
│  • 修复模拟考试交卷与计时相关问题      │
│  • 改进自定义题库导入的稳定性          │
│  • 优化本地数据保存与错误反馈          │
│  • 更新弹窗现在可以查看完整更新说明    │
│                                      │
│  [稍后]                 [立即更新]    │
└──────────────────────────────────────┘
```

#### 更新元数据格式

建议沿用当前版本检查服务的接口和地址，只在现有版本信息结构中增加可选的 `releaseNotes` 字段。若当前更新源已经提供等价的 changelog/description 字段，优先复用，不要同时维护两套字段。

示例：

```json
{
  "versionName": "1.0.1",
  "versionCode": 2,
  "downloadUrl": "https://example.com/releases/gime-1.0.1.apk",
  "releaseDate": "2026-XX-XX",
  "releaseNotes": [
    "修复模拟考试交卷与计时相关问题。",
    "改进自定义题库导入的稳定性。",
    "优化本地题库保存与删除的状态处理。",
    "更新弹窗现在会展示版本更新日志。"
  ]
}
```

说明：
- `example.com` 和日期仅为字段格式示例，发布时必须替换为真实、可用的信息。
- `versionName`、`versionCode` 和 `downloadUrl` 应继续由现有更新机制提供，不要在界面代码中写死。
- `releaseNotes` 可以是字符串数组，也可以是带换行的 Markdown/纯文本；具体选择应与当前接口兼容。
- 若版本服务采用静态 JSON 文件，发布时只需更新元数据与 APK 下载地址。
- 若更新日志字段缺失或为空，界面显示简洁的“此版本暂无更新说明”，不应显示 `null`、`undefined` 或空白异常块。
- 对服务端返回的更新日志按纯文本展示；如需支持 Markdown，应使用明确的安全渲染方式，避免把远端内容直接当作任意 HTML 注入 WebView。

#### 推荐数据结构

如果更新信息由 Java 获取后传给 WebView，可统一整理为：

```java
class UpdateInfo {
    String versionName;
    long versionCode;
    String downloadUrl;
    String releaseDate;
    List<String> releaseNotes;
}
```

这只是推荐结构；如果项目已有对应 DTO/JSON 解析结构，应在原结构上扩展，避免重复造轮子。

#### 前后端职责划分

- **Updater.java**：继续负责版本信息请求、下载和安装相关逻辑；解析或透传更新日志字段。
- **MainActivity.java**：在 Android 与 WebView 之间传递结构化更新信息；保证页面准备就绪后再通知前端。
- **index.html**：负责更新弹窗展示、更新日志列表、空状态和加载失败状态，以及“立即更新/稍后”交互。
- **更新元数据服务**：维护发布版本号、下载地址、发布日期和更新日志。

#### 更新状态建议

| 状态 | 弹窗行为 |
|---|---|
| 检查中 | 显示加载状态，避免重复点击 |
| 无新版本 | 显示当前版本已是最新 |
| 发现新版本，日志有效 | 展示版本信息、日志及更新按钮 |
| 发现新版本，日志为空 | 展示版本信息和“此版本暂无更新说明” |
| 版本信息获取失败 | 显示检查失败和重试入口 |
| 下载中 | 展示下载进度；避免重复启动多个下载 |
| 下载失败 | 显示失败原因及重试入口 |
| 等待系统安装 | 保持现有系统安装流程和提示 |

#### 更新日志的内容规则

更新日志应面向普通用户，说明用户能感知到的变化，不写内部代码路径、调试信息或本机路径。

建议 v1.0.1 对外更新日志：

- 修复模拟考试中的交卷和计时流程。
- 提升从其他应用打开或分享题库文件时的导入稳定性。
- 优化自定义题库导入结果提示。
- 改进题库保存与删除操作的状态反馈。
- 增加版本更新弹窗中的更新日志展示。
- 优化部分异常场景下的提示信息。

只有已完成并通过验证的项目才能放入正式发布日志；未完成项不得提前对用户承诺。

### 3.2 发布安全与 WebView 配置

#### WebView 调试

将无条件启用调试的代码改为只在 Debug 构建启用，例如：

```java
WebView.setWebContentsDebuggingEnabled(BuildConfig.DEBUG);
```

验收要求：
- Debug 构建仍可按开发需要调试。
- Release 构建关闭 WebView 调试。
- 检查实际构建变体引用的 `BuildConfig`，避免包名或模块配置导致引用错误。

#### 源码交付材料

- 源码 ZIP 不应包含发布签名密钥、签名密码、本机 SDK/JDK 配置或本机生成产物。
- 将签名文件、密码配置、本机配置和构建产物加入适当的忽略规则。
- 检查发布包内容，而不是只检查 Git 跟踪状态。
- **不要直接更换现有发布签名密钥**：先确认当前用户的覆盖安装要求和可行的迁移策略。
- 不在日志、README、测试报告或版本更新说明中暴露签名信息和本机绝对路径。

### 3.3 模拟考试状态修复

为模拟考试明确区分状态：

- `running`：答题中。
- `submitting`：正在交卷。
- `submitted`：已经交卷。
- `abandoned`：用户确认放弃。

具体要求：
1. 最后一题继续滑动时，只触发一次交卷；交卷后立即退出题目切换逻辑，不再访问已清空的会话对象。
2. 倒计时归零、手动交卷和最后一题触发交卷都调用同一交卷入口，防止重复提交。
3. 考试中按返回键时显示明确选项，例如“继续考试”“交卷”“退出并放弃”。
4. 退出或交卷后清理对应计时器，不能在后台继续计时或再次自动交卷。
5. 普通练习的返回行为尽量保持不变。

### 3.4 文件导入时序修复

- 在 WebView 页面完成初始化并明确报告 JS ready 后，再向页面发送待导入文件内容。
- 页面尚未 ready 时，暂存待处理的 URI 或提取后的文本；ready 后只消费一次。
- 覆盖两类入口：应用冷启动时由其他应用分享/打开文件，以及应用已运行时接收新文件。
- 对导入过程显示清晰状态：读取中、解析中、导入成功、格式不支持、文件过大、读取失败。
- 确保 Android 侧传递的数据进行正确的 JSON/字符串转义，避免题干内容破坏 JavaScript 调用。

### 3.5 导入格式与题目统计

- 导入文件选择器只显示已实现并经过验证的格式。
- 如果本版本不实现旧版 `.doc` 解析器，就不要宣称支持 `.doc`；保留实际支持的 `.docx`、`.txt`、`.md` 等格式。
- 无答案题目数量应从原始解析结果统计，不应在过滤后再统计。
- 明确无答案题的处理策略：保留为不可判分题，或在导入时跳过并告知用户数量和原因。不要在不同提示中给出矛盾数字。
- 不因修复导入逻辑而擅自修改已有题库的标准答案。

### 3.6 本地题库保存与删除可靠性

- 保存新题库时先完整写入临时文件并验证成功，再以安全替换方式更新正式文件；失败时尽可能保留旧文件。
- 删除题库后，只有确认原生删除成功才从界面列表移除；失败时保留题库条目并显示错误。
- Android 文件流使用可靠的资源管理方式，并设置合理的输入大小限制。
- 对写入失败、磁盘空间不足、文件格式异常等情况提供用户可理解的提示。
- 本版本不必一次性完成完整备份/恢复系统，但应避免让失败操作看起来像成功。

1. Release 构建关闭 WebView 调试；源码交付时排除发布签名材料、本机配置与构建产物，不擅自更换现有签名密钥。
2. 修复模拟考试最后一题触发交卷后仍访问已清空会话的问题；统一手动交卷、倒计时交卷和末题交卷入口，并修复返回/退出时计时器的状态管理。

4. 修复无答案题统计；只允许用户选择真实支持的文件格式，不支持的格式要给出明确提示。
5. 改进题库保存和删除的错误处理，避免磁盘操作失败时 UI 假装成功；为文件读取增加资源释放与合理大小限制。
