# GIme v1.0.8

> 版本口径：v1.0.7 已发布；从这一版起，改动计入 **v1.0.8**，直到 1.0.8 发布为止。
> versionCode 8 → 9，versionName 1.0.7 → 1.0.8。

## 一、API Key 回复开头的 null

**现象**：用 API Key 通道提问，回复开头出现一长串 `null`（真机截图是 `llnullnull…你好呀`）。

**原因**：流式首帧（只有 `role`）和纯思维链帧的 `content` 是 JSON `null`。Android 的
`org.json` 在 `optString(k, "")` 遇到显式 null 时返回的是字面量 `"null"`，逐帧拼起来就成了
回复开头的 null 串。

**修复**：`OpenAiStream` 与内置通道的 fragment 解析都先判断 `isNull`，null 一律当空串；
非流式回包里的 `content` / `reasoning_content` / `finish_reason` 同口径。
新增 4 条纯逻辑断言钉住这个行为，不依赖 mock。

## 二、不在答题页就不带题目

大肥鱼面板可以从首页、题库页、错题本打开；旧逻辑只要 `S` 还在，就把上一组题塞进系统提示，
模型会对着已经离开的题回答。

现在只有答题页真的开着（`#quiz.on`）并且当前题存在时，才发送题目上下文；
`get_current_question` 工具在非答题页会明确报错；`list_questions` / `write_*` 不指定题库时
也不会悄悄拿旧题库顶替。

## 三、大肥鱼与网页版 DeepSeek 的会话同步

- 同一个页面会话始终复用同一条上游会话；按 `convKey` 记录 `sid` 与 `parent` 并落盘。
- 切换页面会话时确保网页侧也有对应的一条：已有映射直接复用，没有就补建。
- **网络抖动不再拆会话**：以前复用中遇到超时/断连也会重建上游会话，一次波动就把同一段对话
  拆成两条网页会话；现在只有上游明确说这条会话不可用才重建。
- 会话过期或重建时，把旧的上游会话删掉，避免网页版留下与 App 对不上的孤儿会话。
- 删除页面会话时，无论当前是网页版登录还是 API Key 模式，都通知原生侧删掉对应映射与上游会话。

## 四、接入方式切换：会话隔离

- 每条会话记下建立时的接入方式：`网页版` / `API Key`；旧版本留下的会话标为 `旧会话`，
  第一次发送时绑定当时的方式。
- 中途切换接入方式会**自动新开一条会话**；旧会话留在原来的通道里，不会被新链路继续使用。
- 历史会话列表显示来源标签；另一接入方式的会话置灰，点它只提示、不切换。
- 就算绕过切换入口，锁定的会话也无法发送消息。
- 设置里的「大肥鱼」面板写明规则：两种通道的会话互相隔开，切换会自动新开会话。

## 五、MCP：修改正确答案

新增 `write_answers` 工具（同时暴露给外部 MCP 客户端和大肥鱼自己）：

- 入参：`bank` + `items: [{id, answer: ["A"]}]`；只接受客观题（单选/多选/判断）。
- 选项必须存在；单选/判断只能一个答案；重复字母自动去重并按选项顺序排列。
- 所有条目先校验完再写盘，不会出现一半改了一半报错。
- 主观题没有选项答案，要改参考答案请用 `write_explanations`。
- 工具描述与系统提示都写明：**只在用户明确要求时调用**，不要主动修改题库、解析或答案。

## 七、装机

覆盖安装即可：与 1.0.0–1.0.7 用同一张签名证书，做题记录、错题、收藏、导入的题库、
大肥鱼历史都保留。旧会话第一次发送时会自动绑定当前接入方式。

## 已知限制

- 网页版与 API Key 的会话不能互转历史；跨方式只能新开一条。
- 传输层仍是 OkHttp/Conscrypt（只有 HTTP/1.1、JA3 与浏览器不同），属于结构性差距。
- 大肥鱼的工具调用由模型决定；即使提示里写了「用户没要求就别调用」，也不能 100% 保证
  模型不误调，写入类工具都做了参数与题型校验。
