# GIme v1.0.7

> 版本口径：目前准备的就是 **v1.0.7**，这之后所有大肥鱼相关改动都计入 v1.0.7，不另开 1.0.8。

**这一版只修大肥鱼：把「用着用着被封号」和「API Key 模式不流式」两个问题处理掉。**

## 一、降低网页版封号风险

用手机号登录跑大肥鱼，本质是在用你自己的账号做非官方客户端的事，上游风控判定封号是
**有可能的**。这一版做的是「把流量做得像真人」，不保证不封，但把最明显的两个脚本特征去掉了。

### 原来为什么会被认出来

1. **请求从不带 Cookie。** 真实浏览器每发一个 API 请求都必然带着
   `HWWAFSESID` / `HWWAFSESTIME` / `smidV2` / `ds_session_id`。老版本只带 `Authorization`，
   Cookie 为空——正常浏览器**不可能**发出这种请求，那是最强的自动化特征。
2. **每问一句就新建一个上游会话。** 真人不会每说一句话换一个会话。老版本 `REUSE_SESSION = false`，
   每轮都 `chat_session/create`；若一轮里触发工具调用还会再建一次。

### 改了什么

- 登录时一并保存整串 Cookie（含 httpOnly 的 `ds_session_id`）与 `deepseek-device-id:chat`，
  之后每个请求都带上；退出登录一并清除。
- 补齐浏览器常规头：`x-client-platform` / `x-client-locale` / `x-client-timezone-offset` /
  `x-client-version` / `x-client-bundle-id` / `x-device-model` / `Accept-Language`；
  UA 与登录 WebView 共用同一份（都带 `; Pixel 7`），两条链路不再报出两种浏览器。
  语言与时区按设备取，不写死 `zh_CN` / `28800`。
- 完成请求按真实页面实测对齐：Referer 用会话路径、Origin 只在 POST、Accept `*/*`、
  body 带 `model_type:"default"` / `preempt:false` 且字段顺序一致。
- 补上完成请求的两枚 `x-hif-leim` / `x-hif-dliq`：从官方 HIF 接口（普通 GET，无需 Authorization）
  拉取，按 `x-hif-ttl` 缓存续期，只挂在完成请求上；HIF 的 Set-Cookie 不混进聊天 Cookie 罐。
- 会话复用：同一会话沿用 `chat_session_id` + `parent_message_id`，每轮只发「最新一轮」
  （历史交给上游会话链），闲置 12 小时重建；换页面对话才换链路，过期了第一次复用失败会自动重建一次。
  页面上点「新会话」时会立刻在上游建一条；删除会话时会调 delete 接口把网页侧那条也删掉，
  App 与网页一一对应；建/删失败不挡本地操作。
  **实测 3 轮对话的 `create_session` 从 3 次降到 1 次。**
- 出站节流：两发之间至少 1.2 秒，任意 60 秒内不超过 12 发。建会话与对话都过这个闸，
  等待较久时界面提示「为了账号安全，提问间隔会放慢一点」。
- 一次只跑一轮对话：同一账号不会同时出现两条并行的上游链路。
- 「停止」就是停止：掐断后不再按「网络抖动」重试，不会在背后继续打上游。

### 风险处理

上游连续表达不满（`40300` / 429 / 拦截页）时，这一次直接报错、**不重试**；但不再做
定时熔断，也没有每日次数上限——要不要接着问，交给用户自己判断。

`40301`（PoW 挑战一次性、偶发）与登录失效**不算**风险——前者重试就好，后者要重新登录，
都不代表「你问太多了」。

**答案缓存已删除**：同一道题再问一遍也会真实请求上游，不再有任何本地回放。

## 二、API Key 模式也走流式

原来只有手机号登录那条通道是流式的，API Key 模式要等整段返回才一次性冒出来
（页面里那行 `var live = cfg.builtin ? … : null` 决定的）。

现在新增 `OpenAiStream` 解析标准 OpenAI SSE：逐行读 `data:`、取 `delta.content` 与
`reasoning_content`、认 `finish_reason` 与 `[DONE]`，每帧回抛给页面。两条通道共用一个流式气泡。
上游不认 `stream:true` 时会自动退回一次性解析。思维链同样逐帧显示。

顺带修掉一个会让人摸不着头脑的问题：设了 `Accept: text/event-stream` 之后，
`HttpURLConnection` 在 4xx 上拿不到响应体（`getErrorStream()` 为空、`getInputStream()`
抛 `HttpRetryException`）。现在读不到就把状态码翻成能照做的话：
401 → 换 Key、429 → 歇一会、404 → 检查地址是否少了 `/v1`。

## 三、允许局域网 / 本机的 http 地址

Android 9 起系统默认禁明文 HTTP，而大肥鱼允许自填接口地址——填
`http://192.168.x.x:8080/v1`（自家反代、Ollama、LM Studio）会直接失败，
错误还只有一句「cleartext not permitted」，看不出是系统拦的。

新增 `res/xml/net_sec.xml`：**默认禁明文，只对回环（127.0.0.1 / localhost / ::1）
与私有网段放行**。公网地址仍然必须 https，没有全局放开。

## 四、少请求、少 token

### 少请求的边界

答案缓存已经删除：同一句话再问一遍也会真实请求上游。现在能省的只有系统提示的固定前缀
（人设与工具规则逐字不变，让上游自己的前缀缓存有机会命中）和下面的 token 裁剪。

### token 裁剪（主要针对 API Key 模式）

| 项目 | 以前 | 现在 |
|---|---|---|
| 历史窗口 | 最近 12 条 | 最近 8 条 |
| 工具轮次 | 4 轮 | 3 轮，最后一轮不再给工具定义 |
| 单次工具结果 | 最多 12000 字 | 3000 字（超长先少给几道题，不把 JSON 切坏） |
| 对话里取题默认条数 | 20 条 | 5 条 |
| 输出长度 | 不限制 | `max_tokens: 1200` |

一轮工具调用 + 回答的实际请求体从「12 条历史 + 每轮都带 3 个工具 schema + 最多 12000 字的工具结果」
缩到「8 条历史 + 前两轮带 schema + 最多 3000 字的工具结果」。省的是真金白银，
代价是超长历史会被截断——追问好几轮之后要交代背景时，最好一句话说清。

## 五、回答正文按 Markdown 渲染

大肥鱼回答的**正文**现在按 Markdown 排版：标题、粗体/斜体、行内代码、围栏代码块、
有序/无序列表、引用、分隔线、链接、删除线。思考链不参与解析，用户自己发的消息也不解析。

流式期间仍显示纯文本（每 40ms 重排一次 Markdown 又慢又闪），答完一次性排版；
已落盘的回答按消息 id 缓存**渲染结果**（只缓存 HTML，不缓存答案）。
安全上前转义 HTML 再套标签，图片不加载远程资源；
链接只放行 http/https，点击走系统浏览器，不会把 App 页面导航走。

轻量实现：不支持表格、嵌套列表和数学公式，代码块不做语法高亮。

## 六、会话规则与空会话界面

- 没有消息的会话不算历史：启动、切换、新建时清掉，历史列表只列有消息的会话。
- 当前会话至少有一条消息（用户、回答、报错都算）才能点「+」新开；空会话里点「+」
  只提示「先问一句，再开新会话」，不会叠出第二个空会话。
- 空会话里头像放大、名字「蓝色大肥鱼」和输入框居中，虚线提示在输入框下面；
  发出第一条后输入框滑回底部、头像恢复原大小、虚线提示消失，头部重新显示名字。
  头部始终是 agent 的名字，对话标题只在历史列表里出现。
- 从头部「+」新建时会**留在当前面板**直接切到空会话界面，不再关闭大肥鱼；
  只有从历史面板删光会话时才由删除动作关掉那一层。
- 新建会话时网页侧也立刻建一条；删除会话时调 `chat_session/delete` 把网页侧那条也删掉，
  映射落盘，重启 App 后仍能找到对应关系。

## 三、刷题中途退出续刷

顺序练习在退出时自动保存这一组的状态：当前在第几题、哪些答对、哪些答错、哪些还没作答，
以及多选题已勾选但还没确认的选择。快照按题库分别保存，存在本机。

「最近练习」里的题库行从纯展示变成可点击：点一下回到退出前正在做的那道题，进度、对错
标记和未作答状态都保持原样。题库页的「继续刷」和首页「今日待刷」走同一个恢复入口，
不再只是跳到第一道没刷过的题。整组答完后快照自动清除，下次从头开始。

## 影响范围

只改大肥鱼的连接、正文渲染、会话规则与界面、刷题的中途退出续刷，以及一个网络策略文件。
组卷、导入、统计、MCP、题库与记录存储格式都没动。

## 装机

覆盖安装即可：与 1.0.0–1.0.6 用同一张签名证书，做题记录、错题、收藏、导入的题库都保留。
versionCode 7 → 8，最低 Android 7.0（API 24）。

## 已知限制

- **不能保证不封。** 这一版是把「明显的脚本」变成「尽量像浏览器」，网页版反代的本质没变。
  真被限流时上游会先回错误码，那时应当停手，不要靠重试硬扛。
- 不要用这个通道批量刷题、不要长时间挂着自动重试、不要在多个设备上同时用同一个账号。
- 上游协议是私有的，随时可能变。变了的症状是报 `40300` / `40301` 或解析不出正文。
- 登录态过期（一般几周）后报「登录态失效，请重新登录」。
- 仍与真实网页不同：传输层是 OkHttp/Conscrypt（只有 HTTP/1.1、JA3 不同），也没有页面资源与埋点流量；
  这两项属于结构性差距，补头解决不了。
- 正文 Markdown 是轻量实现：表格、嵌套列表、数学公式不解析，代码块不做语法高亮。
