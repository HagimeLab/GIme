# GIme v1.0.7

**这一版只修大肥鱼：把「用着用着被封号」和「API Key 模式不流式」两个问题处理掉。**

## 一、降低网页版封号风险

用手机号登录跑大肥鱼，本质是在用你自己的账号做非官方客户端的事，上游风控判定封号是
**有可能的**。这一版做的是「把流量做得像真人」，不保证不封，但把最明显的两个脚本特征去掉了。

### 原来为什么会被认出来

1. **请求从不带 Cookie。** 真实浏览器每发一个 API 请求都必然带着
   `HWWAFSESID` / `HWWAFSESTIME` / `smidV2` / `ds_session_id`。老版本只带 `Authorization`，
   Cookie 为空——正常浏览器**不可能**发出这种请求，那是最强的自动化特征。
2. **每问一句就新建一个上游会话。** 真人不会每说一句话换一个会话。老版本 `REUSE_SESSION = false`，
   每轮都 `chat_session/create`；若一轮里触发工具调用还会再建一次。

### 改了什么

- 登录时一并保存整串 Cookie（含 httpOnly 的 `ds_session_id`）与 `deepseek-device-id:chat`，
  之后每个请求都带上；退出登录一并清除。
- 补齐浏览器常规头：`x-client-platform` / `x-client-locale` / `x-client-timezone-offset` / `Accept-Language`。
- 会话复用：同一会话沿用 `chat_session_id` + `parent_message_id`，每轮只发「最新一轮」
  （历史交给上游会话链），闲置 1 小时重建。**实测 3 轮对话的 `create_session` 从 3 次降到 1 次。**
- 出站节流：两发之间至少 1.2 秒，任意 60 秒内不超过 12 发。建会话与对话都过这个闸，
  等待较久时界面提示「为了账号安全，提问间隔会放慢一点」。

### 使用护栏（三道闸）

| 机制 | 行为 |
|---|---|
| 熔断 | 上游连续 2 次表达不满（`40300` / 429 / 含「频繁」等）就停 10 分钟，**不再重试硬扛**；成功一次清零，用户也可手动「我知道了，继续」 |
| 每日预算 | 每天 60 次，跨天清零，用量落盘（切 App 不能重置）。设置页显示「今日已用 n / 60」 |
| 答案缓存 | 同一道题 + 同一句问法再问一遍，直接复用上次答案，**压根不发请求**。键只由「题目指纹（题干/选项/答案）+ 归一后的提问」决定，不含历史——聊得越久也命得中；LRU 60 条，**并落盘，重启 App 后照样命中**；命中不占每日 60 次预算 |

`40301`（PoW 挑战一次性、偶发）与登录失效**不算**风险——前者重试就好，后者要重新登录，
都不代表「你问太多了」。

API Key 模式不受这些限制：官方额度按量计费，不存在封号问题。

## 二、API Key 模式也走流式

原来只有手机号登录那条通道是流式的，API Key 模式要等整段返回才一次性冒出来
（页面里那行 `var live = cfg.builtin ? … : null` 决定的）。

现在新增 `OpenAiStream` 解析标准 OpenAI SSE：逐行读 `data:`、取 `delta.content` 与
`reasoning_content`、认 `finish_reason` 与 `[DONE]`，每帧回抛给页面。两条通道共用一个流式气泡。
上游不认 `stream:true` 时会自动退回一次性解析。思维链同样逐帧显示。

顺带修掉一个会让人摸不着头脑的问题：设了 `Accept: text/event-stream` 之后，
`HttpURLConnection` 在 4xx 上拿不到响应体（`getErrorStream()` 为空、`getInputStream()`
抛 `HttpRetryException`）。现在读不到就把状态码翻成能照做的话：
401 → 换 Key、429 → 歇一会、404 → 检查地址是否少了 `/v1`。

## 三、允许局域网 / 本机的 http 地址

Android 9 起系统默认禁明文 HTTP，而大肥鱼允许自填接口地址——填
`http://192.168.x.x:8080/v1`（自家反代、Ollama、LM Studio）会直接失败，
错误还只有一句「cleartext not permitted」，看不出是系统拦的。

新增 `res/xml/net_sec.xml`：**默认禁明文，只对回环（127.0.0.1 / localhost / ::1）
与私有网段放行**。公网地址仍然必须 https，没有全局放开。

## 四、少请求、少 token

### 缓存命中率

1. **系统提示拆成两段。** 第一段是人设与工具规则，**每次逐字相同**；第二段才是当前题目。
   上游按前缀命中缓存，题目要是拼在第一段末尾，用户一换题整段前缀就分叉，固定那部分永远命不中。
2. **缓存键只看「哪道题 + 问的什么」。** 题目指纹 = 题干 + 选项 + 答案；提问先归一
   （去空白、折大小写、去首尾标点）。历史不参与，聊到第 20 句也照样命中。
3. **缓存落盘。** 以前只在内存里，App 一重启就清零；现在写进应用私有配置（最多 60 条、
   总量不超过 256KB，按新到旧取），第二天再问同一道题也不发请求。
4. **API Key 模式另有一层页面缓存。** 那条通道不走原生护栏，所以页面自己记一份：
   键含「题目 id + 你选的选项 + 归一提问」，**只有纯问答才缓存**——带工具调用的结果依赖题库状态，
   回放可能过时。命中时对话里会出现一行「直接复用上次回答，没有再请求模型」。

### token 裁剪（主要针对 API Key 模式）

| 项目 | 以前 | 现在 |
|---|---|---|
| 历史窗口 | 最近 12 条 | 最近 8 条 |
| 工具轮次 | 4 轮 | 3 轮，最后一轮不再给工具定义 |
| 单次工具结果 | 最多 12000 字 | 3000 字（超长先少给几道题，不把 JSON 切坏） |
| 对话里取题默认条数 | 20 条 | 5 条 |
| 输出长度 | 不限制 | `max_tokens: 1200` |

一轮工具调用 + 回答的实际请求体从「12 条历史 + 每轮都带 3 个工具 schema + 最多 12000 字的工具结果」
缩到「8 条历史 + 前两轮带 schema + 最多 3000 字的工具结果」。省的是真金白银，
代价是超长历史会被截断——追问好几轮之后要交代背景时，最好一句话说清。

## 影响范围

只改大肥鱼的连接与流式部分，以及一个网络策略文件。刷题、组卷、导入、统计、
MCP、题库与记录存储格式都没动。

## 装机

覆盖安装即可：与 1.0.0–1.0.6 用同一张签名证书，做题记录、错题、收藏、导入的题库都保留。
versionCode 7 → 8，最低 Android 7.0（API 24）。

## 已知限制

- **不能保证不封。** 这一版是把「明显的脚本」变成「尽量像浏览器」，网页版反代的本质没变。
  真被限流时上游会先回错误码，那时应当停手，不要靠重试硬扛。
- 不要用这个通道批量刷题、不要长时间挂着自动重试、不要在多个设备上同时用同一个账号。
- 上游协议是私有的，随时可能变。变了的症状是报 `40300` / `40301` 或解析不出正文。
- 登录态过期（一般几周）后报「登录态失效，请重新登录」。
- 缓存按「题干 + 选项 + 答案 + 问法」判定同一道题：如果只改了这道题的解析、题目本身没变，
  再问同一句话仍会拿到旧答案。设置页的「清缓存」可以立刻清掉（含磁盘那份）。
- 缓存键没把「是否已判分」算进去；原生那层也没把「你选了哪个选项」算进去（页面缓存算了）。
  想最保险，换选项后换个问法再问。

  [25] 缓存落盘 / 固定前缀 / token 裁剪 28 项；新增 `RiskGuardTest`（72 项）与
  `OpenAiStreamTest`（10 项），`DeepSeekClientTest` 补了缓存键原料（提问归一、题目指纹）的用例。
- 真机实测（debug 包，`adb` + CDP）：
  - 会话复用：3 轮对话只 1 次 `create_session`（改造前 3 次），请求头确认带上
    `Cookie`(318 字符) / `x-device-id` / `x-hif-leim` / `x-client-platform`。
  - 流式（API Key 模式，指向本地按标准 OpenAI SSE 回的 mock）：正文切成 3 字符碎片，
    实测收到 **19 帧**（思维链 5 帧 + 正文 14 帧），证明是逐帧解析而非攒完一次性返回。
  - 网络策略：logcat 确认 `Using Network Security Config from resource net_sec`。
- 未实测：熔断触发与恢复的界面表现、缓存命中的界面提示。逻辑层有 45 项单测兜底，
  但手机在本轮多次掉线，界面文案还没在真机上逐条看过。
