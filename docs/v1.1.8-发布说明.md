# GIme v1.1.8

> 版本口径：v1.1.7 已发布（versionCode 18，发布件 `release/GIme-v1.1.7-4e235173.apk`，
> GitHub Release `v1.1.7`）。该版之后到本次定版之间的全部工作归 **1.1.8**（versionCode 19）。
> 安装包由 `signing/gime-release.jks` 签名（与上一版同一张证书），可直接覆盖安装升级，
> 题库、做题记录、方案、对话历史都不动。

## 一、这一版做了什么（一句话版）

把"字幕"从「要么联网取官方字幕、要么没有」变成「本机离线就能出」：自研加速推理框架 + X-ASR
升级量化版在本机跑，模型按需下载、不进安装包；同时把播放器在真机上暴露的三处硬伤
（退全屏黑屏、控制条读不清、选集看不出进度）逐条修掉。

## 二、本地字幕：模型与安装包彻底解耦

- **模型不进安装包**：`app/build/outputs/apk/release/app-release.apk` 里只有推理运行时
  （`libonnxruntime.so`、`libsherpa-onnx-*.so`、`libxasr_jni.so`），没有任何模型权重。
  装完是 66.7 MB，字幕功能要用户自己点一下下载模型（161 MB）才可用。
- **模型说明改成实话**：面板从「X-ASR 中英大模型（1920ms 快模型）· MatMul int8 + onnxsim」
  改为「X-ASR 中英语音识别模型经过自主量化 MatMul、Conv，以及 onnxsim 折叠动态 Shape」——
  写清量化落在哪些算子、Shape 是怎么折的，而不是拿一个耗时数字当卖点。
- **段首说明同步**：由「加速推理框架 · X-ASR 在本机离线生成」改为
  「由自研的加速推理框架 + X-ASR（升级量化版）在本机离线生成字幕，需要先下载模型，才能提前生成字幕」。
- **模型下载双源**：Gitee Release `v1.1.8-models` 的 9 个分卷（20 MB 一卷）为国内首源，
  失败自动降级到 GitHub Release 直链，再降到 GitHub 分块 API（4 MB 一块 + Range 续传）。
  断点按卷记，中断后再点一次只补没下完的卷，整包拼好后校验 SHA-256 才解压。

## 三、播放器：退全屏不再黑屏，控制条能读清

- **退全屏黑屏**：上一版把"全屏播放器"整块缩回卡片，而那块是被 100vh×100vw 黑底包着的，
  缩回的每一帧都带着一大块黑，还要在旋转层上逐帧重绘圆角——用户看到的是"大范围黑屏 + 卡顿"。
  现在结构在同一帧回位，播放器只做 3.5% / 260 ms 的落定回弹、页面 160 ms 淡入，全程不出现铺屏黑。
- **小窗控制条**：底部渐变压到 `.62` 时白字会糊进亮画面。改成三段渐变（`.26` / `.70`），
  时间码加 600 字重与投影、图标加 `drop-shadow`、轨道提到 46% 白并带暗光晕。
  时间码原来被进度线从中间划开（22 px 的块塞 21 px 的字），现在块抬到 20 px、行高压到 1.2。
- **「⋯」按钮**：它复用了列表底部"加载更多"的样式类（`margin: 16px auto 4px` + `width: max-content`），
  结果比同排按钮低 6 px、宽被撑到 42 px。换成独立类右对齐，三个点从 `···` 文本改成三颗 4 px 实心圆。
- **选集列表**：正在播的那一集从"描边小方块"改成通栏列表里唯一一张卡（色带 + 左侧短竖条 +
  反白集号 + 只给它一条 2 px 进度线），竖条与集号之间留 6 px；其余行只留一道 1 px 细线。
  双百分比（`2% 100%`）拆开：当前行写「看到 16%」，字幕就绪只在当前行给一个小 `CC`。

## 四、通知栏

- 小图标换成设计稿那张线稿（猫耳少女头像）：按 24 dp 逐档生成 mdpi→xxxhdpi 位图，
  线稿先放大 2× 加粗再缩回目标尺寸，否则 1 px 灰线在浅色通知卡上等于看不见。

## 五、分发：两个下载源都在

| 产物 | GitHub | Gitee |
|---|---|---|
| 安装包 | Release 资产 `GIme-v1.1.8-0fdb43e4.apk`（直链，按 tag 取） | Release `v1.1.8` 附件（国内首源） |
| 字幕模型 | Release 资产 `gime-asr-xasr-1920ms-int8.zip`（直链） | Release `v1.1.8-models` 的 9 个分卷 |
| 文本清单 | `release/latest.json`（仓库 + jsDelivr 四入口 + raw 兜底） | `hagemilab/gi` 的 raw |

客户端顺序：安装包先试 Gitee Release，再 GitHub Release 直链；清单先试 Gitee raw，再 jsDelivr 四入口，最后 GitHub raw；
模型先试 Gitee 分卷，再 GitHub 直链，最后 GitHub 分块 API。任一源能下完即止。

这一版起**安装包不再提交进仓库**：66MB 的包过不了 GitHub Git Data API 的 blob 单次上传上限
（`422 input too large`），而本机 git 协议推 github 一直被 reset；仓库里没有对象，jsDelivr 也就没有可直出的路径。
所以安装包只留两个发布资产入口，仓库里只放清单（`latest.json`）与源码。

## 六、未做 / 已知边界

- 模型包 161 MB 仍走"按需下载 + 分卷续传"，没有做断点跨设备迁移；换机要重下。
- 官方字幕那一路没动：部分视频没有上游 AI 字幕，切过去会空。
- 选集 `swipePage` 双 `.page.on` 的历史隐患未修（只在脚本兜底时暴露，正常点击不复现）。
- 浅色主题下 `--ink-3` 的对比度 2.09:1 偏低，属已知可接受项，本版未动。
