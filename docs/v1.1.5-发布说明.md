## 一、这一版做了什么（一句话版）

把「问大肥鱼」这条路补齐成能真正递东西给它看：图片从相册多选、边选边传、传完能点开看大图，
网页版登录时它是真的看得到图；顺手修掉网页版思考链一跳一冻、发出后没反馈，
并把长文本输入改成按需悬浮展开。

## 二、改动明细（按提交）

### 1. 思考链摊帧（a4e8c04）

- 内置通道（DeepSeek 网页版）的真机抓包：`onChatStream` 增量间隔 **p50=1ms / p95=999ms**，每条固定 24 字
  （正撞在 `DeepSeekBridge.Streamer`「攒够 24 字就发」的上限），照实画就是「跳一大块 + 原地停一秒」。
- 正文本来就有摊帧（`liveText`/`pokeLive`），思考链绕过了它。补上同一条流的另一路 `liveThink`/`pokeThink`
  （每 28ms 铺 `max(3, 剩余/8)` 字），收尾统一走 `chatLiveSettle`：**两条泵都摊完**才关 `live`。
- 不动原生 Streamer：那是「不碰 DeepSeek*」的既有边界，且摊帧对两条通道都要（Key 通道也会攒批）。

### 2. 找回「大肥鱼正在想…」（5886b68）

两条独立成因，都在发出后那一刻让屏幕空白：

- **读盘消息一律算答完**（`chatSettleRestored`，启动两条分支 + 切会话共三处读盘口）。回答中途被杀掉时
  收尾前已经落过一次盘，`live:true` 被写进记录；读回来不清掉，`chatHasLive()` 从此恒真，
  而等待气泡的条件是 `chatBusy && !chatHasLive()` ⇒ 那颗泡永久不再出现（顺带也让正文不解析 Markdown）。
- **链没摊出字时仍显示打字泡**：上一笔引入的回归——`hasThink` 看的是全量链，链刚到、`shownThink` 还是 0
  的那一瞬间，空的思考盒把打字泡顶掉了。改成看摊出的视图（`!!thinkView`）。

### 3. 附件入口分两项（fddc739）

- 回形针不再直接拉文件选择器，先弹小浮窗「发给大肥鱼」：**上传文件**走原来的抽取链路，
  **上传图片**走相册多选（`pickChatImages` → `ACTION_OPEN_DOCUMENT` + `EXTRA_ALLOW_MULTIPLE`，`image/*`）。
- 选中的图落在输入框上方一排缩略图（点 × 撤一张，最多 6 张），配不配文字都能发。

### 4. 网页版真能看到图（a0ccf93）

- 复刻 DeepSeek 网页版本来就有的文件引用：`POST /api/v0/file/upload_file`（multipart 字段 `file`，
  带 `x-thinking-enabled / x-model-type / x-file-size`，**PoW 按这个 target_path 单独算**，一次性不能复用）
  → 拿 `file-<uuid>` → `GET /api/v0/file/fetch_files` 轮询到 `SUCCESS` → 完成请求挂 `ref_file_ids`（只挂第一轮、只在登录通道）。
- 上传的是压缩后的图（最长边 1600、JPEG 85），文件名保留图片扩展名（上游按扩展名判类型）。
- 分寸：只有 id 到手才写「图已随消息提供，可以直接看图」；没传上去**一句话都不写**（只本机 toast）——
  这句会进上游会话历史，写过的「我看不到」会在后面真带图的轮次里被一直复读。

### 5. 图片边传边显（6ecc819）

- 图一放进输入区就开始传，多选**一张一张来**（上一张回包才走下一张）；发送时直接用已到手的手续，不再现传。
- 进度是**真字节数**：`HttpNet` 分块写 32KB 一报，Cronet 自定义 `UploadDataProvider` 每读一段回报，
  原生按「≥4% 且 ≥150ms」节流推 `onChatImageProg`。
- 显示用「清晰从上往下露出来」：缩略图两层，底层常模糊、上层清晰按 `--p` 走 `-webkit-mask-image`，露到哪儿就是传到哪儿；
  99% 停住，最后 1% 由「解析完成」那条回调给。上传中禁发送（按钮「上传中」），但 × 撤图一直可点。
- 踩坑已钉：`getLength()` 给定长后 Cronet 走非分块，`onReadSucceeded(true)` 抛
  `Non-chunked upload can't have last chunk` ⇒ 定长上传永远传 `false`。

### 6. 三点收口 + 两处交互（357ad3c、b804093）

- **附件浮窗点外面收回**：背后铺一层 `.att-scrim`（z 999，夹在对话 990 与浮窗 1000 之间，18% 暗），
  与卡片悬浮窗同一口径；返回键/点选项那条路走 `closeLayer` 的 `sheet3Closed` 钩子擦掉拦截层，不留残影。
- **上传状态行**：缩略图下面一行 `正在上传图片… →（已传好 N 张）→ 上传成功`，最后一张落地补一句 toast；
  有失败按红字说清「几张没传上去、几张可以发」。
- **聊天里的图片可点开看大图**：选图时申请持久读授权、把 `content://` 原图地址随消息记录；
  点开先铺缩略图，原生按地址缩到最长边 1280 回原图（新桥方法 `viewChatImage(uri, req)`，带编号，
  换一张或已收回就丢弃）。老消息没记地址的停在缩略图。
  顺带修 `pickedImageUris` 每批清零的缺陷：连着选两批图会把前一张传成新批的图，现在 idx 是全局序号。
- **OpenUI 生成中有气泡**：组件源码还在流的时候挂一颗「大肥鱼生成中…」（与等待气泡同样式同位置），
  卡片装上那次重画一起消失；围栏出现/消失会打破「只改文本节点」的快路径（`m._liveUiGen`）。
- **输入框长文本悬浮展开**：删掉「内容由大肥鱼生成，可能有误；以题库解析为准」那一行（空行不占高），
  常驻展开按钮改成超过 60 字才露出，点它把**同一颗输入框**搬进浮窗（不复制第二份，值与光标都在），
  「收起」/返回键/连带关对话都由 `closeLayer` 钩子把节点放回原位。
  留白跟着按钮走（`.chat-field.with-more`），且先定留白再量高度——否则刚从长文本删回来会多占一行。

## 四、验收结论

- 本地（Edge 360×780@3x）与真机（白牌 M600 Pro，Android 11，WebView 80）双轨验过：
  浮窗点外面收回（真点）、上传状态三态、真实相册多选上传到「上传成功」、
  点开气泡图片回 **576×1280 原图**（跨进程用持久授权取回）、悬浮输入窗（键盘态 331×344 / 收起键盘 557 高）、
  11 字无按钮 44px / 77 字带按钮 96px / 删回 11 字仍 44px。
- 用户数据未被写入：每轮测试前后 `localStorage` 的会话串长度一致（134360 字），消息条数不变，测试消息只在内存注入并当场还原。
- 遗留：真机「我的 → 检查更新」的下发确认需要在手机联网时点一次；发布件本身按四入口 + raw 兜底核验（见验收文档）。
