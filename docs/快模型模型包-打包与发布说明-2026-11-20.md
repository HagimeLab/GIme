## Gitee 国内中转（已上线）

仓库：<https://gitee.com/hagemilab/gi>，发行版 tag **`v1.1.8-models`**，9 个附件：

```
https://gitee.com/hagemilab/gi/releases/download/v1.1.8-models/gime-asr-xasr-1920ms-int8.zip.p1
…                                                                              .p2 … .p9
```

为什么要切卷（Gitee 帮助中心核实）：

- 发行版**单个附件 ≤ 100MB**（GVP 200MB），单仓库附件总量 1GB —— 169MB 整包传不上去。
- 附件下载**不支持 Range**（实测响应头无 `Accept-Ranges`）—— 断了只能整卷重下。
- 单连接 30MB 以上容易提前断流 —— 所以沿用旧包验证过的 **20MB 一卷 × 9 卷**。

App 侧对应逻辑：`AsrModels.giteeSingle()` 按卷下，每卷先写 `.part` 再改名，下好一卷落盘一卷，
中断后再点一次只补没下完的卷；9 卷齐了拼成整包，长度 + SHA-256 双校验通过才解压。
分卷目录 `files/asr/xasr.gparts/`，装完即删。

**重新发布（换包或补卷）**

```bat
python tools\pack-model.py --dir D:\desktop\加速推理框架\models_1920_int8\sim ^
    --out dist\gime-asr-xasr-1920ms-int8.zip
python tools\split-model.py --src dist\gime-asr-xasr-1920ms-int8.zip --out models\gitee-parts
:: 令牌可从凭据管理器取，或自行设 GITEE_TOKEN（需 projects 写权限）
python tools\upload-gitee.py --dir models\gitee-parts --tag v1.1.8-models
```

脚本是幂等的：已传过且大小一致的卷直接跳过，只补缺的。

## App 侧改了什么

| 位置 | 改动 | 原因 |
|---|---|---|
| `AsrModels` | `MODEL_URL` 直链 + `Model.url` 字段；`urlDownload()` 单连接 + `Range` 续传，长度 + SHA-256 双校验后解压 | 换任意静态地址都能下，不吃 GitHub API 配额 |
| `AsrModels` | `USE_GITEE_MODELS = true`，分卷从 8 改 9；下载顺序 **Gitee 首源 → 直链 → GitHub 分块** | 国内用户先走 Gitee；Gitee 挂了自动降级，不弹错 |
| `AsrModels` | Gitee 失败且没有直链/assetId 时，改报「已存 N%，再点一次可续传」并直接收工 | 否则会去打 assetId=0 的空号，用户看到的是 HTTP 404 天书 |
| `AsrModels` | `installed()` 同时认旧包（epoch-99 四件套）；`progressPct` 计入未拼完的部分 | 老用户升级不误报未安装；续传进度不回到 0 |
| `AsrModels` | 分块目录只在 GitHub 分块路径创建 | 修掉直链/分卷分支留下空 `xasr.parts/` 的问题 |
| `TrackBuilder` | Rust 门禁改为 `encoder.onnx` **或** 旧慢模型名任一在位；`sherpaReady()` 缺失时抛明确异常 | 否则快模型装上了 Rust 也不启动，或静默交空轨 |
| `AsrEngine` | 自检的模型存在性检查兼容 `encoder.onnx` | 与门禁口径一致 |
| `AsrEngine` / `MainActivity` | 自检入口写 `selftest enter`；新增 debug-only `Android.asrProbe()` | 这台机 logcat 抓不到输出，只能靠落盘标记与探针 |
| `build.gradle.kts` | `versionCode 19` / `versionName 1.1.8` | 新包配新版本 |

## GitHub 侧的限制（重要）

169MB 单文件**进不了 git 仓库**：GitHub 对普通 push 的硬限制是单文件 100MB，超了直接拒收；
`.gitignore` 里本来就写了 `/models/*.zip`。所以「随总体推送一起推入 GitHub」有三种可行姿势：

1. **GitHub Release 资产**（推荐，单资产上限 2GB）：把 9 卷用同样的文件名传上去，App 只需再加一条
   「GitHub 分卷」降级分支即可，Gitee / GitHub 两站同构，改动很小。
2. **Git LFS**：github.com 免费额度 1GB，169MB 放得下，但用户拉取走 LFS 端点、且依赖 LFS 服务可用。
3. **切到 <100MB 再入库**：比如 2 卷 84MB，能 push 但仓库永久背 169MB 历史，不推荐。

现在 Git 客户端在这台机器上没有安装（`git`/`gh` 都不在 PATH），也没有 `GH_TOKEN`，所以 GitHub 那一步等你的推送通道。

## 已知取舍与限制

1. **包里没有慢模型**（按你的选择）。sherpa 回退只在「老用户本地还留着 epoch-99」时可用；新用户 Rust 加载失败会明确报「字幕引擎不可用：本地模型加载失败，且包内不含回退模型」，不会静默出空字幕。
2. **`MODEL_TAG` 没动**（仍是 `xasr-480ms-int8`）：旧字幕轨继续有效，新轨标签显示口径仍写 480ms，不影响播放。
3. **老用户升级路径**：本地是旧 480ms 包 → 新 APK 显示「已安装」但还跑慢模型（0.75 RTF）。要换快模型得在设置页删掉模型再下一次 169MB。
4. **Gitee 是免费 CDN**：无 Range、单连接易断、20MB 一块已是实测较稳的档位；如果哪天被限流，App 会自动降到下一条源。
5. `asrProbe()` 与 `selftest enter` 是 debug-only 诊断口子，Release 里 `asrProbe()` 直接返回 `release`。
