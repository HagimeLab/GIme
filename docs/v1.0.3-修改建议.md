# GIme v1.0.3 更新方案（五项功能与分支合并）

## 版本基线

- 当前发布版：GIme `1.0.2`，`versionCode = 3`，包名 `com.fan.shuatiku`。
- 1.0.3 发布时将版本名更新为 `1.0.3`、版本码提升为 `4`，沿用当前正式签名，保证覆盖安装和本地数据兼容。
- 当前本地 `release/v1.0.1` 与 `main` 指向相同提交；远端 `origin/release/v1.0.1` 与 `main` 已分叉。合并前必须确认用户所指的 1.0.1 分支引用及期望保留的提交，不能仅按分支名直接合并。

## 版本集成前置项：合并 v1.0.1 分支

- 在 1.0.3 功能实施分支上合并用户指定的 `v1.0.1` / `release/v1.0.1` 分支，保留需要的提交并逐项处理冲突。
- 当前分支图显示本地 `main` 与本地 `release/v1.0.1` 相同，但远端 `origin/release/v1.0.1` 相对 `main` 有分叉提交（`main...origin/release/v1.0.1` 为 29/14）。因此实施前要核定是合并本地分支还是远端分支，并审阅双方独有提交；避免把历史版本分支中的旧实现覆盖 1.0.2 已有修复。
- 合并完成后先确认更新下载、导入、模拟考试、设置持久化等 1.0.2 行为仍在，再叠加本方案功能。该项是版本集成要求，不是已执行的合并操作。

## 本次已明确范围

### 1. 首页顶部三个圆形元素对齐，头像换成应用图标

**目标效果**

- 首页问候栏中的头像、主题切换按钮、学习统计按钮处于同一水平线上，视觉中心和尺寸一致。
- 将目前显示字母 `G` 的头像替换为 GIme 应用图标，即那只眯眼猫的轮廓（叼草那根已去掉）。
- 保留主题切换和学习统计的现有点击行为，不改变问候文案和首页搜索入口。

**代码现状与实现建议**

- 相关布局在 `app/src/main/assets/index.html` 的首页 `.hello` 区域；目前头像容器 `.avatar` 为 44px，两个 `.icon-btn` 为 42px，父层已有 `align-items:center`。建议统一三个元素的外框尺寸和对齐规则，避免尺寸差造成的视觉偏差。
- 美术的唯一来源是 `design/cat-light.png` / `cat-dark.png`（同一条线稿的黑墨、白墨两版，已入库）：`python3 design/make_icons.py` 从它们派生出启动页的 `app/src/main/assets/cat-light.png`、`cat-dark.png`（墨色从 `index.html` 的 `--ink` 令牌读，不抄第二份）和各密度的 `app/src/main/res/mipmap-<dpi>/ic_launcher.png`，别手改产物。启动页两套主题各挂一张 `<img>`，由 `[data-theme]` 切换；不走 CSS mask——真机（WebView Chrome 80）挂上 mask 后整只猫被裁没，桌面 headless 也复现不了，已退回两图方案。
- 图标在浅色和深色主题下都应有清晰边界，并保持圆形头像容器的裁剪、留白与触控布局稳定。

**验收标准**

- 头像、主题、统计三个圆形元素的水平中心线一致，视觉尺寸一致；窄屏和字号变化时不挤压问候文本或产生换行错位。
- `G` 被猫轮廓图标替换，图片加载失败时页面仍可正常显示。
- 主题按钮仍可切换主题，统计按钮仍打开学习统计；首页搜索题库入口不受影响。

### 2. 修复震动开关状态与实际反馈不一致

**目标效果**

- “震动反馈”开启时，答题判分按当前规则提供短震/长震。
- 关闭时，答题判分不触发设备震动。
- 设置切换后立即生效，应用重启后状态仍保持。

**代码现状与排查重点**

- 设置保存在 `localStorage` 的 `stk.settings.v2`；设置项在 `renderMe()` 生成，点击后由 `toggleSet('haptics')` 更新并保存。
- 判分处调用 `vibrate(...)`，当前 `vibrate` 函数包含 `if (!set.haptics) return` 的开关判断。因此不能只在 UI 上改开关；实施时应沿完整调用链复现用户报告，并检查历史设置值的类型/规范化、开关写入与读取、所有震动调用点。
- 建议加载设置时将 `haptics` 归一为布尔值，并在震动函数中采用明确的开启条件（仅 `set.haptics === true` 才调用 `navigator.vibrate`），避免字符串等异常旧值被当作开启。确认关闭状态不被迁移逻辑意外重置。

**验收标准**

- 开启：答对触发短震、答错触发长震。
- 关闭：答对和答错都不产生设备震动；页面动画/颜色反馈可以继续显示。
- 切换开关后立即验证；强制关闭并重启后再次验证设置持久化。
- 自动检查中用 `navigator.vibrate` stub 分别验证开/关状态的调用次数；真机再验证实际触感，覆盖正确答案和错误答案。

### 3. 删除“我的”页的搜索题目入口，保留首页搜索

**目标效果**

- 删除“我的”设置列表中的“搜索题目”行。
- 首页“搜索题库 / 知识点”按钮保持不变，仍可搜索题库/知识点。
- 不删除搜索面板或搜索逻辑，也不影响其他明确使用该搜索面板的入口。

**代码现状与实现建议**

- “我的”列表由 `renderMe()` 生成，其中有 `row("search", "搜索题目", ...)`；该行通过 `row()` 的 `search` 分支调用 `openFS('search')`。
- 首页搜索按钮也调用 `openFS('search')`，因此只移除“我的”列表这一行，不移除共用搜索功能。若确认没有其他调用方，再清理专门服务于已删除行的冗余分支。

**验收标准**

- “我的”页不再显示“搜索题目”。
- 首页搜索按钮仍显示且可正常打开搜索界面；关键词检索结果和关闭行为正常。
- 其他页面原有搜索功能（若有）不受影响。

### 4. 移除全部内置题库，所有题库由用户导入并可删除

**目标效果**

- 应用不再自带题目数据；新安装后显示清晰的空状态和导入入口。
- 所有题库都由用户导入，题库列表中的每个题库均可由用户确认后删除，不再区分“内置题库只能隐藏”和“导入题库可以删除”。
- 首页、题库分类、搜索、错题、收藏和模拟组卷在没有题库或仅有部分导入题库时都能正常工作。

**代码现状与实现建议**

- 题库目前由 `app/src/main/assets/bank.js` 提供内置数据；个人题库由 Android `MainActivity.loadBanks()/saveBank()/deleteBank()` 读写应用私有目录，再由页面 `bootImportedBanks()` 合并到 `BANK`。
- `renderBank()` 当前按 `s.custom` 决定显示“删除”或“隐藏”，并提供隐藏题库恢复入口；`renderMe()` 还会显示恢复隐藏题库。移除内置题库后，应删除/清理隐藏恢复状态和内置/导入分支，统一题库删除确认与原生文件删除结果处理。
- 首次启动及升级后都可能没有可用题库。应保证总题数为 0 时不出现 NaN/Infinity，首页统计、最近练习、题库筛选、搜索结果、错题/收藏和组卷可用空状态；显著展示“导入题库”入口。
- 不能只把 `bank.js` 置空：现有 `tools/check.mjs` 将内置 subjects/questions 非空作为通过条件，其他页面也默认题库存在。需要一起调整页面初始化、统计边界、导入/删除逻辑与回归检查，使空题库成为正式支持状态。
- 删除任意题库后应同步更新运行时题库、题目索引、统计、错题/收藏数据和正在进行的答题/考试会话；只有磁盘删除成功才从 UI 移除。删除操作需二次确认，并提示题库相关记录是否一并删除。

**升级数据迁移需确认**

- 1.0.2 用户升级后，旧内置题库对应的做题记录会变成无题目可关联的数据。建议清理失效的进行中会话，并避免旧记录误关联到之后导入的同 ID 题目；历史统计是否一并清除，应在实施前明确并向用户说明，不应静默丢弃。
- 已导入的个人题库应继续保留在应用私有目录中，升级后仍能加载、练习和删除；移除内置题库不能误删用户导入的数据。

**验收标准**

- 全新安装无默认题目，界面引导用户导入；导入成功后题库出现在首页和题库列表中。
- 所有题库都显示统一删除操作；确认后删除，取消不改变数据；磁盘删除失败时题库仍留在列表。
- 删除最后一个题库后应用可正常使用，统计为 0、搜索/错题/组卷显示合理空态，仍能再次导入。
- 从 1.0.2 覆盖升级后，旧内置题库不再出现，先前导入的个人题库保留；旧数据迁移行为符合确认后的策略。
- 反复导入、删除、重启后列表和磁盘内容一致；不会因同一题库重复加载而重复计数。

### 5. 新增填空题、解答题分类并适配导入；六个分类卡片可动态展开/收起

**目标效果**

- 首页“题库分类”在单选、多选、判断之外，新增填空题和解答题；连同真题套卷共六个分类卡片。
- 导入 DOCX/TXT/MD 时识别并保留填空题、解答题类型及其答案/参考答案、解析，不误判成单选题，也不因没有选项而被过滤掉。
- 六个分类卡片都支持动态展开/收起，包含一致的动画、触控状态和展开后的分类信息。

**代码现状与实现建议**

- 当前 `TYPES` 仅有单选、多选、判断、真题套卷四项；首页 `.cats` 使用单行 `display:flex`。题型过滤器、`typeName()`、判分逻辑和 `tools/check.mjs` 的合法题型集合也仅覆盖三种客观题。
- 导入解析 `parseBankText()` 目前通过答案字母和选项结构推断题型；`onImportText()` 只保留有答案且选项至少两项的题目。因此填空题/解答题需要明确格式识别规则、数据结构、可用题目过滤规则和显示/练习流程，不能只增加两个分类图标。
- 建议增加可扩展的题型字段及非选择题答案字段；填空题进入练习时提供文本作答与参考答案核对，解答题提供题干、参考答案/解析查看和自我核对。非客观题是否自动判分、如何纳入正确率与模拟考试成绩需在实施前确认。若没有可靠的自动判分规则，不应把主观题伪装成自动正确/错误。
- 导入适配应识别常见“填空题/解答题”题型标记、填空占位符、答案/参考答案和解析；同时保留当前选择题、判断题解析能力。导入报告应分别统计各题型成功数、无法识别数及缺失参考答案数。
- 六个分类卡片的动态展开/收起交互按“卡片可点开/收起分类内容”理解；具体展开内容、默认状态、是否允许同时展开多个及动画幅度尚需确认。交互需支持触屏、键盘/无障碍状态，并尊重减少动态效果设置（如项目后续提供该设置）。

**验收标准**

- 首页显示六个分类：单选、多选、判断、填空、解答、真题套卷；数量与实际导入题目一致，无题型时显示 0 或约定的空状态。
- 填空和解答样例能从 DOCX/TXT/MD 正确识别题干、类型、答案/参考答案及解析；不满足规则的题目在导入报告中说明，不静默丢弃。
- 填空/解答题可正常进入练习并按确认后的规则核对；统计与模拟考试结果不把主观题错误地作为客观选择题判分。
- 六个分类卡片均可展开和收起，动画无明显跳动；快速连续点击、题库为空和低屏幕宽度下布局正常。
- 旧版单选/多选/判断题库导入、筛选、练习和统计保持兼容。

### 6. 支持 PDF 题库导入（本次追加）

**目标效果**

- 导入入口除 Word（.docx）/ txt / md 外，再支持 PDF，覆盖「题库只有 PDF 版」这一最常见的实际情况。
- PDF 必须有文字层才导得进来；扫描件、图片版、加密文件要明确说明原因并给出下一步动作，不能静默变成「导入成功但 0 题」。
- 微信 / 文件管理器里「用其他应用打开 → GIme」打开 PDF 也能进导入流程。

**实现要点**

- 依赖 `com.tom-roush:pdfbox-android:2.0.27.0`，并 `exclude(group = "org.bouncycastle")`。BouncyCastle 只服务于「打开加密 PDF」和验签，而本项目的策略本就是拒绝加密文件，排除后 release APK 从 9.18MB 降到 3.01MB。
- 新增 `PdfText`（PDFBox 取文字，`setSortByPosition(true)` 保证双栏/表格不串行）与 `PdfTidy`（纯 Java，去汉字间多余空格、判定是否可用，可桌面单测）。
- 拒绝规则集中在 `PdfTidy.rejectReason(text, pages)`：无文字层 → 提示 OCR；私用区/替换符占比 > 20% → 提示编码乱码、换来源；字数 < 页数 × 12 → 报页数并提示 OCR。
- `TextExtract` 的 `.pdf` 分支先把流落到 `cacheDir` 的临时文件再解析（PDF 要随机访问整个文件），finally 删除。
- 部分文件管理器把 PDF 报成 `application/octet-stream`、`DISPLAY_NAME` 也可能没有后缀，因此按文件头嗅探（`%PDF` / `PK\x03\x04`）兜底。
- `AndroidManifest.xml` 的 VIEW intent-filter 增加 `application/pdf`、删掉实际不支持的 `application/msword`。

**验收标准**

- 文字版 PDF 能导入并正确识别题型、答案、解析；题号、选项、答案行不串。
- 扫描件 / 空白页 / 加密 / 损坏四种文件分别给出可执行的提示，且不写入题库。
- 导入说明写清「PDF 需要有文字层」，用户不会把扫描件当成功。
- 导入统计（收录 / 无答案 / 缺选项 / 重复）在 PDF 与 Word 两条路径上口径一致。
## 待确认的交互与判分规则

- 填空题是否支持多个空、多个可接受答案、答案顺序及大小写/标点容错。
- 解答题采用“查看参考答案后自我标记掌握/未掌握”，还是仅浏览答案；是否纳入模拟考试及成绩。
- 六个分类卡片展开后显示题目列表、操作入口还是题型说明；默认展开状态以及单开/多开规则。
- 扩展导入格式中题型标记的具体写法与答案字段命名；建议先提供一份标准示例模板，减少识别歧义。

## 建议实施与验证顺序

1. 确认并合并目标 `v1.0.1` 分支，先回归合并后的 1.0.2 基线。
2. 调整首页头像资源与三个圆形元素尺寸/对齐。
3. 复现震动开关问题，再修复设置值归一和实际震动调用门控；先做逻辑检查，再真机验证。
4. 移除“我的”搜索行，回归首页搜索。
5. 移除内置题库并实现用户题库的统一导入、删除和空状态，确定旧内置题库记录的迁移策略。
6. 扩展题型模型、导入识别、练习与统计，并实现六类卡片展开/收起；先确认判分和交互规则。
7. 完成后更新版本号至 `1.0.3` / `versionCode 4`，运行项目现有回归检查，构建 Debug/Release，并验证从 1.0.2 覆盖升级及个人题库保留。
