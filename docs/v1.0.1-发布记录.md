## 产物与提交的对应关系

`aapt2` 与 `apksigner` 只能证明「这是 1.0.1、由这张证书签的」，证明不了「由哪个提交构建」。
所以另外做了两件事：

1. 从 tag `v1.0.1` 指向的提交做**干净检出**并构建，与工作区构建逐条目比对：
   `classes*.dex`、`resources.arsc`、`assets/*`、`AndroidManifest.xml`、`res/*` **全部逐字节相同**，
   唯一差异是 `META-INF/version-control-info.textproto`（记录构建时的 git 状态）。
2. 工作区构建的该文件写着 `revision: "<提交哈希>"`，与 tag 完全一致；
   干净检出因 worktree 无 `.git`，该文件是 `NO_VALID_GIT_FOUND`。

**因此正式发布件取「干净检出」那一份**：它不含任何工作区状态，
且已逐条目证明与 tag 提交构建出的代码一致。

> 注意：APK 构建默认不可复现（同一提交两次构建的整包 SHA-256 不同），
> 差异仅在上述 git 元数据文件。不要用「整包哈希相同」作为可复现构建的判据。

## 发布后自检

```powershell
pwsh -File tools\verify-release.ps1 -Tag v1.0.1
```

脚本会：确认 release 存在且 tag 匹配、未处于 draft、APK 与源码包的大小/摘要与本地一致、
源码包内无敏感文件。**上传错文件（比如传了含 .git 的工程压缩包）会在这一步被抓出来。**

## 本次发布前修掉的数据安全问题

- `saveBank()` 原实现先 `delete()` 旧文件再 `renameTo()` 新文件，rename 失败即丢题库。
  已改为「写临时文件并落盘校验 → 旧文件挪成 `.bak` → 新文件顶上 → 删 `.bak`」，失败一律回滚。
- 崩溃恢复边界：若进程死在「旧文件已挪成 `.bak`、新文件未顶上」之间，
  原 `cleanup()` 只是「不删」孤儿 `.bak`，而 `loadBanks()` 只认 `*.json`，题库会永久消失。
  已改为把孤儿 `.bak` **还原**成正式文件。真机上手工制造该现场并验证恢复后题库可正常出题判分。
