# GIme v1.0.3

**这一版加进 PDF 题库导入，移除内置题库，并把界面动效整体做了一遍。**

## 这一版改了什么

### 导入 PDF 题库

- 文字版 PDF 可以直接选来导入，题目、选项、答案、解析一起识别。
- 扫描件（整页是图片）和加密 PDF 导不进，会明确告诉你原因，不会给你一个空题库。
- 导入文案统一：以前写 docx 的地方现在写 PDF；题库名会自动去掉 `.pdf` 后缀。
- 从微信「用其他应用打开 → GIme」这条路也走同一条导入流程。

### 不再内置题库

- 上一版随包带的那套内置题库已经移除，**升级后首页会是空的，需要你自己导入**。
- 做题记录、已导入的题库、错题本、收藏都不受影响（与旧版同一张签名证书，覆盖安装即可）。
- 分类区可以整体收起，占位更小。

### 界面动效

- 启动页：圆形揭幕 → 首页交错浮入，首帧底色跟着上次用的主题走，不再闪白。
- 点题库卡片进答题页改成共享元素转场：卡片放大进入，返回时缩回原位。
- 答题页改成上中下三段布局，「上一题 / 确认 / 下一题」那一排常驻，不再随长题滚走。
- 题库卡左滑弹出的操作条，现在可以右滑收回。
- 底部标签的胶囊会跟着手指流动；选项按钮按压有回弹。
- 深色模式开关：点下去开关和标题当场翻转（以前要等换肤动画放完），
  标题也跟着主题显示「深色模式 / 浅色模式」。
- 换肤落定那一帧掐掉元素自身的过渡，修掉首页六张分类卡闪一下深浅的问题。
- 设置里的开关不再触发触摸震动（震动反馈只管答题对错）。
- 应用图标与启动页换成同一只猫。

### 修掉一个崩溃

这台机器的 WebView 在页面内跳转时会退化成本地文件调用，以前会让进程直接崩掉
（表现为切主题时 App 突然退出）。挂上默认 WebViewClient 后不再发生。

## 已知代价

- **换肤的圆形扩散在旧内核上会掉帧。** 老 WebView 不把 `clip-path` 动画交给合成器，
  每帧要重绘一整层全屏快照。真机量过：一次切换掉 4~8 帧、单帧最长 166~233ms。
  新内核（View Transitions）不受影响。保留这个效果是明确的选择——
  换成纯位移/透明度的动效可以一帧不丢，但深浅两套色板之间插值会路过一层发闷的灰。
- **安装包从 0.95MB 涨到 2.94MB。** PDF 导入带进了 PDFBox，
  它的字体与 cmap 资源约占 2.1MB（未压缩）。
- `prefers-reduced-motion` 目前只盖住了部分过渡，换肤动效不在其列。

## 实测结果

在真机（Android 11 / WebView Chrome 80 那台）上逐项验过：

- 导入 → 解析 → 做题 → 判分 → 错题本 / 收藏 全链路跑通，进度覆盖安装后保留。
- 深浅两套主题各冷启动一次，启动页那只猫、桌面图标三张截图逐张核对。
- 换肤切换逐帧采样，掉帧数与上面「已知代价」里写的一致。
- 更新链路：`release/latest.json` 与 Release 资产双向核对，源码包内容与
  该标签下的仓库树逐路径比对（只少一个 APK，它作为独立资产发布）。

## 安装

覆盖安装即可，做题记录和导入的题库都会保留。最低 Android 7.0（API 24）。
