# GIme v1.0.6

**这一版加两样东西：答题页可以问「大肥鱼」，题库可以被外部 agent 读写。**

## 大肥鱼答疑助手

### 手机号登录一次 DeepSeek，之后不用 API Key、不用电脑

1. 「我的 → 大肥鱼」，或随便进一道题点中间那颗鱼，再点「用手机号登录 DeepSeek」。
2. 输手机号 → 过人机验证 → 填短信验证码。
3. 登录成功后登录页自动关掉，回到对话直接问。

登录态存在应用私有配置里，重启 App 不用再登；换账号或退出在「我的 → 大肥鱼 → 退出登录」。
如果那个 WebView 本来就登录着，点进去会立刻识别并自动返回，不会再要求重复登录一次。

判据是**问上游**，不是看 token 变没变：游客 token 也能建会话，只有 `/api/v0/users/current`
读回 `mobile_number` 才算真登录。网络错误不拉黑 token（恢复后可能还有效），上游明确拒绝才拉黑。

### 两种接入方式二选一，同一时刻只显示一套

面板顶部只有一个切换按钮，第一行写「现在用什么」、第二行写「点下去会换成什么」：

- 手机号登录：地址恒为内置通道，页面上没有 Key 这个概念，只显示登录态（脱敏手机号）和退出登录。
- API Key：还是原来的外部 OpenAI 兼容接口，填地址 / 模型 / Key 三项。

切换只改一个字段，另一套的输入值原样留着，切回来不用重填。老数据没有该字段时按地址推断，升级后行为不变。

### 对话本身

- 回答改成流式输出，边想边显示；思考过程单独一块，点标题可展开收起。
- 底部导航中间新增大肥鱼入口，不要求先进某道题；答题页那颗鱼会带上当前题目上下文。
- 支持新建会话，也能翻看和删除历史会话。
- 网络不好自动重试（最多两次，对话里会出现一条「正在重试 n/2」的灰字）。已经流出一部分正文后**不重试**，
  宁可报错，也不让用户看到重复答案。
- 等太久可以点「停止」（忙时「发送」按钮会变成它）：立刻掐断原生连接，不用干等超时，停止不保存半截回答。
- 「我的 → 大肥鱼」底部可调「对话字号」（A− / A＋，80%~150%，默认 100%），只作用于气泡和思考链，
  能叠加「我的 → 字号」的全局缩放。

### 上游是怎么连上的（给之后维护的人看）

登录接口要求人机验证令牌（数美 / hCaptcha），只能真人真浏览器产生，程序不能也不该伪造，
所以这一步做成「真人登一次，App 只搬走登录结果」；实测上游只强校验 `Authorization`，
Cookie 与各类 `x-*` 设备头可省略，因此不必在手机上保存整套浏览器指纹。

对话走私有 SSE 方言，请求要带 PoW。PoW 用的 Keccak 变体（只跑 23 轮）是纯 Java 实现、多线程暴破，
本轮实测 20000 次哈希 0.06 秒（约 33 万次/秒），难度 144000 全窗口 0.4 秒、平均 0.2 秒；
每个挑战只能用一次，所以每次请求现取现算。

分层：`DeepSeekBridge`（认内置地址、跑完整轮对话、按 OpenAI 回包形状返回）→
`DeepSeekClient`（messages + tools 拍平成一个 prompt，把模型吐的 tool_call 解析回标准结构）→
`DeepSeekWeb`（建会话、算 PoW、解析 SSE）+ `DeepSeekHashV1` + `DeepSeekLoginActivity`。
页面侧代码一行没改。细节见 `docs/大肥鱼直连DeepSeek.md`。

## MCP 接口

应用内置一个 MCP 服务（Streamable HTTP，JSON-RPC 2.0），只监听 `127.0.0.1:8765/mcp`，
让外部 agent 直接读写 App 里的题库：

| 工具 | 作用 |
|---|---|
| `list_banks` | 列出当前题库 |
| `import_bank` | 把一段文本按 App 导入格式解析成新题库（支持 `dryRun` 只预览不落盘） |
| `list_questions` | 提取单题或多题与选项（可按题库、id、题型、关键词、分页） |
| `write_explanations` | 写或改解析与主观题参考答案，支持 replace / append，一条或多条 |

- **默认常开**：页面就绪即启动，应用关掉才停；没有开关，也没有配置面板（本版已删掉上一版那个手动面板）。
- 口令仍然要：每个请求带 `Authorization: Bearer <口令>`。取口令看应用启动时打的那行日志
  `adb logcat -s GImeMCP`。怀疑泄露就清掉应用的 `shared_prefs/mcp.xml`，下次启动换新口令。
- 电脑上的 agent 先 `adb forward tcp:8765 tcp:8765`，或用仓库里的 `tools/gime-mcp.mjs` 走 stdio。
- 工具分发在页面 JS 里，和 App 内「导入」「写解析」走同一份代码，不存在第二套口径。
- 只绑回环地址，不做局域网监听；**没有删除题库的工具**，删除仍在界面里做。

细节见 `docs/MCP接口.md`。

## 影响范围

新增的是页面里两块（对话 + MCP 工具层）和原生几个类。刷题、组卷、导入、统计的既有逻辑没动，
题目数据与做题记录的存储格式没变。

## 装机

覆盖安装即可：与 1.0.0–1.0.5 用同一张签名证书（证书 SHA-256 见发布记录），
做题记录、错题、收藏、导入的题库都会保留，不需要卸载。
versionCode 6 → 7，最低 Android 7.0（API 24）。

## 已知限制

- 上游协议是私有的，随时可能变。变了的症状是对话报 `40300` / `40301`（PoW 相关）或直接解析不出正文，
  需要按新的抓包更新 `DeepSeekWeb`。
- 内置通道默认不复用上游会话：每轮重发完整历史，代价是每轮多一次建会话的往返（实测整轮仍在一秒量级）。
- 登录态过期（一般几周）后报「登录态失效，请重新登录」，重新登一次即可。
- 手机号登录这条通道依赖原生侧，PC 侧预览读不到状态时那一行副标题显示「仅手机版可用」，
  此时改用 API Key 方式。
- 大肥鱼是模型生成的回答，界面里固定标了「以题库解析为准」；它以工具读到的题库为准，不是它自己的记忆。
- MCP 服务默认开着，等于本机任何应用都能尝试连回环端口——口令校验挡在前面，
  但在手机上插着 adb 的场合，日志里那行口令是可见的（只有拿到 adb 的人看得到）。

## 验证

- 回归：`tools\check.cmd` 全过——页面逻辑 **367 项**、发布目录 **10 项**；Java 各套件全过
  （版本比较 9、题库存储 29、下载状态 9、多源回退 13、PDF 清洗 30、文件头识别 8、
  Keccak 与 PoW 15、OpenAI 协议层 41、MCP 服务回环与口令 10、清单 15）。
  本版新增的检查段包括：MCP 工具层、大肥鱼对话、DeepSeek 协议层、对话字号（27 项）、
  MCP 常开与提示词（13 项）。
- 真机（MCP，跑在 1.0.6 debug 包上）：通过 `adb forward tcp:8765` 端到端跑过 initialize、tools/list、list_banks、
  错口令 401、通知 202、`dryRun` 预览、真实导入、list_questions 取选项与答案、
  write_explanations 替换与追加并落盘；测试题库测完已删除。
- 真机（对话与界面，同样是 debug 包）：悬浮控制条、对话面板上滑、两种接入的切换与对话字号都逐轮在手机上看过；
  页面侧的 agent 循环（工具调用 → 写解析 → 汇总回答）用桩住原生接口的方式跑通，
  模型的真实回答要联网与真实凭证，本轮没跑（`DeepSeekLiveTest` 不进回归）。
- 正式包（release 签名）还没在手机上装过：装机要过安装守护的验证码，试的那一会儿手机在锁屏休眠。
  签名不是障碍——debug 与 release 用的是同一张证书（构建脚本里 debug 故意复用发布钥匙，
  两个包的证书 SHA-256 逐字相同），所以正式包可以直接覆盖 debug 包，不用卸载、不丢记录。
  真正与签名有关的限制只有一条：**release 包没有 WebView 调试 socket**，要在手机上量 DOM 仍得先装 debug。
