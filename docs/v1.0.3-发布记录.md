### 为什么包大了 2.1MB

本版加 PDF 导入，带进 PDFBox。按未压缩量排前几名：
`assets/com/tom_roush/pdfbox/resources/ttf/LiberationSans-Regular.ttf` 411KB、
十几个 `fontbox/resources/cmap/*` 各 170~330KB。这是功能代价，不是打包失误。

## 本版内容

功能与文案的逐条依据在 `docs/v1.0.3-修改建议.md`（本版基线），这里只记发布侧要留的账：

- PDF 题库导入（文字版可导；扫描件、加密件说明原因），题库名去掉 `.pdf` 后缀。
- **移除内置题库**：`assets/bank.js` 留成 `window.BANK = {subjects: [], questions: []}` 的空壳，
  升级用户拿到合法空结构，不会走进兜底分支。首页因此变空，需要自己导入——
  这条写在更新弹窗正文里，不藏。
- 启动页揭幕 + 交错浮入 + 首帧底色跟随主题；共享元素转场；答题页 flex 外壳；
  底部胶囊流动；选项按压回弹；分类区整体收起。
- 深色模式开关：状态在手指落下那一帧落地、标题跟随主题、换肤落定那一帧掐掉元素过渡。
- 挂默认 `WebViewClient`，堵住这台 ROM 的 WebView 在页面内跳转时退化成本地文件调用而崩进程。
- 应用图标与启动页换成同一只猫。

## 换肤这一格的两笔账（写清楚，免得下一轮又当新发现）

1. **圆形扩散在老内核（WebView Chrome 80）上必掉帧。** 真机逐帧采样：一次切换掉 4~8 帧、
   单帧最长 166~233ms。原因是 `clip-path` 动画不进合成器，每帧重绘一整层全屏快照——
   同一层换成纯色也丢 4 帧，去掉全部阴影只从 8 降到 6，加 `will-change: clip-path` 无效。
   换成纯 `transform`/`opacity` 的动效可以一帧不丢，但那是渐变不是扩散，
   深浅两套色板之间插值会路过一层发闷的灰，用户明确不要。所以保留效果、认下掉帧。
2. **首页六张分类卡闪深浅**是另一件事：换色那一帧真界面被 `.cat` 自己的
   `background .2s / box-shadow .24s` 带着爬，爬完比快照淡出还晚。修法是在换色那一帧
   挂两帧 `transition: none`。量到修法前 644→690→742→788ms 三档中间色，修法后一次跳变到位。
