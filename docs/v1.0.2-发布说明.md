# GIme v1.0.2

**这一版修「点了更新一直卡在 0%、下载不了」，并把下载源换到国内 CDN。**

## 为什么会有这个问题

v1.0.1 的更新弹窗能正确显示新版本和更新日志，但点「立即更新」后可能永远停在 0%，
没有任何提示。真机复现后确认是两个原因叠加：

1. **网络层**：下载地址会重定向到 `release-assets.githubusercontent.com`，
   这个域名在部分网络下直接连不上。实测 `api.github.com` 正常（所以能检查到新版本），
   但下载时报 `failed to connect to github.com:443 after 20000ms`。
2. **代码层**：下载器进入「等待重试」状态后，程序把它当成「还在下载」，
   于是一直转圈、后台无限重试，界面上什么提示都没有。

## 这一版改了什么

### 下载源换到国内 CDN

- 安装包随源码放在仓库的 `release/` 目录，由 **jsDelivr 直接提供**，
  不再经过 GitHub 的资产域名。实测手机端命中缓存后 28ms 就能拿到完整文件。
- **多个下载源自动回退**：依次尝试 jsDelivr 的四个入口
  （cdn / fastly / testingcf / gcore），最后才回落到 GitHub 原始地址。
- **下载路径带版本号**：jsDelivr 对同一路径缓存 7 天，固定文件名会导致发了新版还下发旧包。
  每个版本是独立路径（如 `release/GIme-v1.0.2.apk`），发布即生效。

### 不再假装在下载

- 下载前先快速探测各个源，连不上就直接告诉你，不再让你干等。
- 识别「等待重试」状态，按失败处理并停止后台重试。
- 即使连接没断但长时间没有数据，25 秒后也会停止并提示。
- 下载失败时提供「打开发布页」，可以在浏览器里手动取安装包。
- 修掉「连接中」标题在开始下载后没有切回「正在下载」的问题。

### 版本清单

版本号与安装包文件名统一由仓库里的 `release/latest.json` 声明，
避免出现「说有新版本、下载地址却 404」这种对不上的情况。

## 实测结果

在测试机上完整跑通了一遍更新：

1. 旧版点「立即更新」→ 从 jsDelivr 开始下载
2. 进度真实推进：0% → 35% → 93% → 完成
3. 下载到的文件 949,653 字节，SHA-256 与源码构建产物**逐字节一致**
4. 自动拉起系统安装页 → 安装成功

## 如果你仍然下载不了

这是网络环境问题，不是 App 的问题。请点更新弹窗里的 **「打开发布页」**，
在浏览器里下载 `GIme-v1.0.2.apk`。

## 安装

覆盖安装即可，做题记录和导入的题库都会保留（与旧版同一张签名证书）。
