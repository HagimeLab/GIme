# GIme v1.1.0

> 版本口径：v1.0.9 已发布；这一版只换美术——应用图标和启动页那只猫换成新线稿。
> versionCode 11，versionName 1.1.0。

## 一、新线稿入库

`design/cat-light.png`（黑墨白纸）/ `design/cat-dark.png`（白墨黑纸）是美术的唯一来源，
两张 2048×2048、同一条线稿的两版。两版墨迹外接框一致（29,66,2031,2048 与 27,66,2031,2048），
所以浅色和深色启动页取景对得上。

产物全部由 `python3 design/make_icons.py` 派生，不手改产物 PNG：

- 启动页两张 256×256 剪影，墨色从 `index.html` 的 `--ink` 令牌读（#14161A / #F2F3F5）；
- 五档 `mipmap-*/ic_launcher.png` 与 1024 母图。

中途出现过一版用 Pillow 代码手绘猫娘头像的图标（`draw_app_icon()`，168 行）。用户裁定图标直接用原图，
该废稿已随 `make_icons.py` 回退丢弃：从未提交，也没有任何已发布产物带过它
（`dist/` 里最新的是 18:58 的 v1.0.9 源码包，早于那批手绘产物）。

## 二、图标单独一档留白

启动页和图标原本共用 5% 留白。桌面图标会被启动器遮罩裁切，共用一档时脸在 tile 里太小，
所以图标拆出独立的 `ICON_MARGIN`，真机三轮裁定：22% → 14% → 12%，脸占 tile 从 69% 到 81%。

边界（同一把尺：192px 产物上被内切圆切掉的墨迹比例）：

| 留白 | 脸占 tile | 纯圆遮罩切掉 | 切到哪儿 |
|---|---|---|---|
| 22% | 69% | 0% | 不切 |
| 14% | 78% | 1.3% | 只有底部两角发梢（y≥158） |
| 12%（本版） | 81% | 2.9% | 从 y=19 起，耳尖开始被擦 |

测试机这台 Freeme 启动器用圆角方形遮罩，12% 下两只耳尖完整；换到 Pixel 类纯圆启动器会露出来。
这条代价随边界表一起写进了 `make_icons.py` 的产物说明，不是只留在本文。

## 三、启动页那只猫放到 82px

新线稿的笔画只有旧坐猫的一半粗（同一把尺：2.4px vs 5.0px @256 画布），原来 62 CSS px 在真机上又细又小。
先放到 84，真机看过后裁定收到 82。真机量得猫墨迹宽 ÷ 圆盘宽 = 77.2%，CSS 设定是 82/104 = 78.8%。

82px 时有 14/9182 个墨点（0.15%，底部发梢）越出 104px 圆盘边线，真机上看不出来，
因此没有给 `.sp-logo` 加 `overflow:hidden`。

## 四、产物一致性

装机包里五档 `ic_launcher` 与仓库产物逐像素相同，`assets/cat-*.png` 逐字节相同。

这里有个坑要记下：AGP 的 `optimizeReleaseResources` 会把资源改名成 `res/9w.png` 这类短名并重压缩 PNG，
所以按路径找会 MISSING、按 md5 比必 DIFF。判包里到底是哪一版，只能 `aapt2 dump resources` 反查映射后逐像素比。

## 七、代价与限制

- 12% 留白在纯圆启动器下会擦耳尖，见第二节边界表。
- 深色版启动页忠实还原第二张原图：那张图眼白是实心白，暗底上呈两团白眼、脸偏面具感。
  这是两张原图本身的差异，脚本不做二次加工；要改得动 `design/cat-dark.png` 那张图。
- 启动页仍是"两套主题各一张 img"，没走 CSS mask：真机 WebView Chrome 80 和桌面 headless 两边都量过，
  挂上 mask 后整只猫被裁没。
- 本版没有新增美术相关的自动检查项（`check.mjs` 不覆盖启动页与图标）。换图的正确性目前只靠
  脚本单一来源加真机截图，这是下一步该补的口子。
