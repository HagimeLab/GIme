# GIme · 刷题 App

应用名 **GIme**，图标是那只叼草的猫（母图 `design/ic_master.png`，五档 mipmap 由它缩放出来）。把四份华为题库合并成一个离线刷题 App，装在安卓机上刷。无网络请求，题目和做题记录都在本机。

## 装到手机

APK 在 `app\build\outputs\apk\debug\app-debug.apk`（约 1 MB）。

方式一（数据线）：

```
C:\Users\fan\Tools\platform-tools\adb.exe install -r "D:\desktop\刷题apk\app\build\outputs\apk\debug\app-debug.apk"
```

方式二（不连电脑）：把 `app-debug.apk` 发到手机上点开安装，需要允许「安装未知来源应用」。

## 模式

顺序练习 / 随机刷题 / 背题模式 / 错题重刷 / 收藏题目 / 模拟考试（交卷才判分）。

**组卷设置**（首页「组卷出题」、题库页「模拟」、首页「真题套卷」都进同一个面板）：

- **题库可以多选**：四个题库任意组合，右上角「全选」一键切换；每行显示该库题数。
- **按总题数**：从所选题库合起来的池子里随机抽 N 题（N 上限 = 池子大小）。例：勾 HCIP + ICT 两库，滑到 40 → 从这 484 题里随机抽 40。
- **按题型分配**：分别设单选题、多选题、判断题各要几道，0 表示不要这类，上限随所选题库变化。例：单选 20 + 多选 10 + 判断 5 → 各按各的数目抽，合起来 35 题。
- 两种模式都保留「全部随机多少题」这条路径（按总题数模式即是）。
- 时长 5–45 分钟可调；答题页顶部会显示这张卷子的来源（如「HCIP-Cloud Service + ICT 大赛 计算赛道」）。
- 越界会被钳制：请求数超过所选题库能提供的量，自动降到上限。

答对**不会**自动跳下一题，停在当前屏让你看完解析，手动点「下一题」。深色模式、字号、清空进度在「我的」tab 里改；收藏的题目点「我的 → 收藏」即可单刷。进度和错题存在 App 本地，**卸载或清除数据会一起没掉**。

判分反馈（黑白灰下靠形态与动效，不用颜色）：答完出现一条**黑底白字大号结果条**「✓ 回答正确 / ✕ 回答错误 · 正确答案 ABD」，同时顶部 Toast、答错整块左右抖动、页面闪一下底色的动效、手机震动（答对短震、答错长三段）。

错题本是一份**你自己维护的清单**：答错自动进；点「标记错题」手动加，按钮变成黑底「移出错题本」，再点一下移出。**后来答对不会自动移出**（最新一次对错只记进统计，不影响归属），要清掉只能手动移出或用「管理」批量清；再答错会重新进来。移出只影响错题本成员，不动正确率统计。

## 解析的来源

四份题源里**只有 106 题自带解析**——`HCIP` 和 `ICT` 两份通篇没有「解析」二字，`Storage`/`Cloud` 两份的解析还因原文档排版换行被截成半句（如「务器，虚拟路由器等功能。」）。剩下 851 题的解析是**按华为知识点逐题撰写**的，口径统一为「先讲正确项依据，再点出干扰项错在哪」，60～140 字。

所以 App 里解析标题旁带来源标记，**只用形状区分、不引入颜色**：实心胶囊 = 题源原文，虚线框 = 撰写。被截断的题源残句没有丢，原样存在该题的备注里（「题源原解析（排版截断）：“……”」）。

撰写时定了三条红线：不编造版本号/参数名/默认值/指标数字，不确定就只讲原理；判定题给答案本身错了的，不为自圆其说编理由；题干残缺的明说缺什么。因此有 **68 题的解析以「（存疑）」或「（题干不全）」开头**，逐条汇总在 `build/explain_review.md`。

**这批标记里最要紧的发现：ICT 计算赛道那份题源的答案键有系统性错误**（约 19% 被判定与官方行为不符，例如「不属于 SSH 客户端工具」给的答案是 `ssh`，而 `rsync` 才是；`wa` 高定位故障点给 `ps aux`，应为 `iotop`）。撰写代理回查过 `raw/ict_calc.txt`，确认**差异来自原题库答案键，不是本项目抽取时引入的**。这些题的答案我一个都没改——改答案等于改被测量的量——只在解析里写明按原理应当是哪个，交给你自己对照权威资料定夺。刷题时请把「（存疑）」开头的解析当参考而不是结论。

## 数据上的已知问题（照实说）

- **3 题没有答案**，是题源本身就没给，不是解析丢了：`HCNA-Storage 第 147 题`（原文写「答案：我也不知道」）、`ICT 第 4 题`（原文答案栏空白）、`HCIP 第 197 题`（选项块是纯文本，无勾选状态也无答案行）。这三题在 App 里会显示「题源未标注本题答案 · 此题不判分」，也**没有**解析——没有正确答案就无从解释。
- **2 题在题源里出现两次且答案不一致**，App 保留第一处答案，并在题干下方红字标出另一处答案，供你自己判断。
- **23 题带红色备注**，内容是「答案应该是 C」这类原书读者的勘误批注，以及跨页题/翻拍题的溯源说明（例如某题原图只拍到 3 个选项）。备注不改印刷答案，只并列显示。
- HCIP 那份是截图，识别时可能出现错字；题干的英文产品名（DDM、CSE、RestSchema 等）已逐页复核过 6 道残题。

## 改题库 / 重新打包

题目数据在 `app\src\main\assets\bank.js`（`window.BANK = {...}`）。直接改这个文件，或改完源文件重新解析，然后双击：

```
build.cmd
```

`build.cmd` 里临时把 `JAVA_HOME` 指到 JDK 21，不动系统默认的 Java 8（eNSP 要用 8）。构建产物路径会在命令结束时打印。

## 工程结构

```
app/src/main/
  AndroidManifest.xml              无网络/存储权限；注册了微信「其他应用打开」的 VIEW/SEND 接收
  java/com/fan/shuatiku/MainActivity.java   WebView 外壳 + 文件选择器 + JS 桥（存/读/删题库文件）
  java/com/fan/shuatiku/TextExtract.java    docx(zip+xml)/txt/md 抽正文，红字用 \u0001\u0002 包起来；零依赖
  assets/index.html                全部界面、题目解析、样式（单文件）
  assets/bank.js                   内置 960 题
```

题目解析放在页面 JS 里而不是 Java 里，是为了能用无头浏览器直接测：同一份真实题源文本分别喂给 JS 解析器和当初建库的 Python 解析器，逐题比对（`tools/difftest.py`）。

## 界面

配色严格只有黑、白、多级浅灰，**没有任何彩色**；卡片统一大圆角 + 柔和弥散的 Neumorphism 双向阴影（浅色下左上高光、右下淡影），无尖锐棱角；无衬线字体，标题加粗、正文常规。

因为不允许用红绿，**答对/答错靠形态区分**：

| 状态 | 形态 |
|---|---|
| 选中未判分 | 内凹（inset 阴影） |
| 答对（选中且正确） | 黑底白字 + ✓，题干上方「回答正确」黑底胶囊 |
| 选错 | 虚线描边 + ✕ + 文字压淡 |
| 正解但没选 | 浅灰描边 + 右侧「答案」小标签 |
| 未选未涉 | 整体压淡 |

判分反馈另有震动（答对短震一下、答错三下），不依赖视觉。

页面结构：底部 4 个 tab（首页 / 题库 / 错题本 / 我的）。首页含问候+头像+铃铛、圆角搜索框、题型分类四宫格（单选题·多选题·判断题·真题套卷）、今日待刷题任务列表（带复选框与剩余题量）、最近练习（完成量与正确率）。答题页从右侧推入：返回箭头 + 题型标题 + 答题卡入口、进度条、题干卡、A/B/C/D 大圆角选项卡、收藏与标记错题行、上一题/下一题、底部完成度。弹层仍按 `advanced-popup-design` 的层级与动效做：底部弹层（答题卡，可跟手下拉关闭）、居中毛玻璃（交卷成绩、危险确认）、Toast、全屏模态（搜索、统计），250ms `cubic-bezier(0.16,1,0.3,1)`，z-index 900/1000/1010/1100 分层。深色模式是同一套灰阶的暗色版本。


## 交互

全部遵守「即时反馈 → 连续反馈 → 明确反馈」，时长 200–500ms，只用缓动不用线性，深浅两套主题下表现一致。

| 交互 | 做法 |
|---|---|
| 主题切换 | 点首页右上角半圆图标，新主题从**手指触点**以圆形向外扩散，半径按到最远角落算；只裁切整页快照，题干/选项/卡片不缩放不变形（View Transitions）。老内核没有这个 API 时改用自建的内容快照层，见下面「换肤的圆形扩散」 |
| 答题页滑动 | 在题目区域**横向**划过 62px 可换上一题/下一题。这条手势必须先定轴：横向位移要明显压过竖向（>1.4 倍）才认作换题，一旦判成竖向就整个放弃、把这一划留给页面滚动。没有定轴时上下滑题目时拇指自然带出的横向漂移就能满足 62px，会被误判成换题（`tools/gesture_test.py` 断言，`tools/gesture_control.py` 是反向对照：把定轴撤回成修复前的代码，四条漂移断言必须 FAIL 而换题断言必须仍 PASS，否则测试是空的） |
| 进度条 | 宽度用 `cubic-bezier(.34,1.56,.64,1)`，先轻微超过目标位置再回弹落准 |
| 解析折叠 | 判分后出现「答案 X · 解析」条，容器高度与内容同步展开/收起，箭头同步转 180°；可在设置里改成答完不自动展开 |
| 吸附滑杆 | 组卷设置里的滑杆：按在哪就跳到哪再跟手拖，松手按**松手速度做惯性投影**后吸附落位，落位带回弹；滑得越快过冲越明显。**档位是 1 题**，刻度只标 0/¼/½/¾/满，所以"40 题"这种具体数字能落准（固定粗刻度会把它吸成 30 或 50） |
| 批量勾选 | 错题本「管理」→「全选」按从上到下每 45ms 勾一项，每项带 5% 弹性放大，不一次性全亮 |
| 卡片删除 | 批量移出时，卡片沿曲线飞向右下角删除图标，途中抬起、缩小、旋转、淡出，逐项隔 70ms |
| 卡片堆叠 | 题库页向上滚动时顶部卡片先粘住，被后续卡片覆盖时逐层压缩、变淡，压缩量随覆盖程度累积 |
| 标签选择 | 题库页题型标签栏（全部/单选/多选/判断）：选中标签变黑底白字并占更大宽度，其余标签主动向两侧让位 |
| 开关联动 | 设置页开关成组（深色模式 / 震动反馈 / 答完展开解析）：拨动某一个，同组其他开关按距离错峰轻震一下，只给视觉反馈、不改它们的状态 |

判分反馈：黑底白字大号结果条 + 顶部 Toast + 答错抖动 + 页面闪底 + 震动（可在设置里关）。

## 屏幕适配

Activity 走边到边：状态栏和导航栏设成透明、WebView 铺满整块屏幕，系统栏实际高度由 `onApplyWindowInsets` 量到后回灌给页面。**不能靠 `env(safe-area-inset-*)`**——WebView 里它恒为 0（那是浏览器自己处理 insets 时才填的），所以页面用 `--sat` / `--sab` 两个变量，由 `window.__insets(top, bottom)` 按 `devicePixelRatio` 换算成 CSS px 写入，再合成 `--st` / `--sb` 供各处 `calc()` 使用。换肤时还会调 `Android.themeHint(light)` 把状态栏/导航栏图标深浅和窗口底色一起改掉。

不做这件事的后果（第一版真机上就是这样）：底部导航栏是一块不透明的白条，页面被吃掉 96px，`.tabs` 正好压在系统返回键下面。

## 换肤的圆形扩散

两条路径，取决于内核，但**扩散波携带的始终是"换肤后的界面"本身**——不能是一块纯色，否则圆扫过的地方内容会被糊掉：

- **支持 View Transitions（Chrome 111+）**：`document.startViewTransition` + `clip-path: circle()` 从触点扩散，另挂一个 900ms 兜底防止转场被 skip 后卡在旧主题。
- **不支持（这台手机是 Chrome 80）**：`themedSnapshot()` 把当前 DOM 复制进一层 `.reveal` 容器（跳过 `<script>`，容器挂上目标主题的 `data-theme`），按 `clip-path` 圆形从触点扩散。**盖满整屏那一刻才真正 `update()` 换肤**，随后快照淡出移除，所以圆内看到的是新界面、圆外还是旧界面，内容全程不消失。快照的 `scrollTop` 同步当前滚动位置，避免页面在波里跳一屏。

四个必须记住的坑：

1. **浅色变量只写在 `:root` 里不够用**。`:root` 就是 `html`，快照层作为 body 的子元素会继承 html 上的深色变量，而它挂的 `data-theme="light"` 匹配不到任何规则——于是深→浅时那个圆**和背景同色，整段扩散是隐形的**，420ms 后整屏一次性跳色（你报的"没扩散到的部分已经先变了色"就是这个）。现在浅色那套变量声明在 `:root, [data-theme="light"]` 上（一份声明挂两个选择器，不是抄两份），任何元素都能自带浅色主题。
2. **Chrome 80 的 WAAPI 只把 `playState` 推到 `finished`，不派发 `Animation.onfinish`**（Blink 到 Chrome 84 才补上事件）。用 `onfinish` 串"动画结束→清理"会永久悬挂，后果是快照层以 `opacity:1` 留在屏上糊住整个界面，App 看着像死掉。现在推进一律按 `setTimeout` 计时，并另挂一道 1400ms 硬清理。
3. **`--sat/--sab`（系统栏高度）不能和浅色色板写在同一条规则里**。为了让快照层能自带浅色主题，色板那条规则改成了 `:root, [data-theme="light"]`；如果 insets 的默认值也留在里面，快照层一旦挂上 `data-theme="light"` 就会顺手把 `--sat` 重置回 `0px`，`.page` 顶部内边距从 45px 变成 18px，**快照内容比真界面高 27px**——圆里圆外错开一截，扩散过程看着就是界面在抖（深→浅才抖、浅→深正常，正因为深色块没声明这几个变量）。现在 insets 单独只挂 `:root`：它是设备事实，不是主题的一部分。
4. **晚到的闭包要用轮次令牌把关**。`setTheme` 每次 `++waveSeq`，所有延迟回调里的 `update()` 先比对令牌，不是自己那一轮就放弃。没有这道闸，连点两次主题键时第一次的 1400ms 兜底会在第二轮中途把主题**翻回旧值**（实测复现：486ms 已变浅色，580ms 又被打回深色）。

对齐可以用 `tools/probe_jitter.js` 复验：它把页面滚到中途再触发换肤，比较快照层与真页面的 `scrollHeight` / `scrollTop`，两个方向都必须逐项相等（`ovSH==docSH`、`ovScroll==scrollY`），同时记录动画全程 `.tabs`/卡片/滚动位置的极差（应全为 0）。

## 导入题库

题库页顶部「导入题库」→ 选文件；也可以在微信里长按文件 →「用其他应用打开」→ 选「GIme」，文件会直接送进 App 走同一条导入流程。

**关于"打开微信选聊天记录"**：第三方 App 做不到——微信没有对外提供"进入某个聊天并选文件"的接口，也没有可被调用的文件选择页。所以走的是两条真实可行的路：App 内调系统文件选择器（在里面可以导航到微信的下载目录），以及微信侧把文件分享给我们。

- 支持格式：`.docx`、`.txt`、`.md`。**不支持 PDF 和老版 `.doc`**：PDF 要在手机上引第三方解析库（APK 会从 1MB 涨到约 10MB）且只能处理有文字层的文件，你那份 HCIP 是整页截图，手机上认不出来；老 `.doc` 是二进制 OLE 容器，手机上抠文本很容易吃进乱码把整批题弄坏。要导这两类，先在电脑上转成 docx 或 txt。
- 识别规则：`1、题干` → `A、选项` → `答案：X` → `解析：…`，题号允许有小断号；`答案：正确/错误/对/错` 会判成判断题；题干里自带的 `1、2、3` 步骤不会被当成新题；一行里塞多个选项也能拆开；同题重复出现自动去重。文档里**用红字标答案**（没有"答案："字样）的，按红字推答案。
- 解析会一起导入，答完题在解析折叠区里能看到。
- 导入过程有进度条：读取 → 提取正文 → 识别题目 → 生成题库 → 导入成功，成功页会报「认出 N 题 / 可用 M 题 / 无答案多少 / 重复多少」。没有答案或缺选项的题会被丢掉，不会混进题库。
- 导入的题库存在 App 私有目录 `files/banks/<id>.json`，卸载即没；启动时自动加载回来。

## 删除 / 隐藏题库

题库页每个卡片**左滑**露出按钮：导入的题库是「删除」，内置的四个是「隐藏」（内置题库编在 APK 里删不掉，只能从列表隐藏）。点下去都会先弹一个确认框，再确认才真删/真隐藏；隐藏后可以从题库页底部的「已隐藏 N 个」或「我的 → 恢复隐藏题库」一键恢复。删除只清这个题库的题目和它的做题记录，不动别的题库。

## 真机验证

在 M600 Pro（Android 11，WebView 内核 **Chrome 80**）上实测过，不是只跑桌面模拟器。这台机器的内核比桌面测试用的 Chrome 老六年，下面几条是只有真机才暴露出来的：

- **`document.startViewTransition` 不存在**（要 Chrome 111+）。主题切换在真机上走的是降级路径：涟漪环 + 直接换色，900ms 兜底保证不会被动画卡住。
- **安卓内核会给点过的按钮画一圈系统橙色焦点环**，破坏"严格黑白灰"。已在 CSS 里去掉 `button/input` 的 `outline`；触屏没有键盘导航，不需要它。
- **`navigator.vibrate()` 静默失效**，因为清单缺 `VIBRATE` 权限——桌面用桩对象测不出来。已补上。
- **系统返回键原本不生效**：`MainActivity` 没重写 `onBackPressed()`，页面里的 `window.onBack()` 是死代码，弹层开着时按返回会直接退出 App。已接上，返回键按 弹层 → 全屏页 → 答题页 的顺序逐层回收。
- **弹层栈会漏**：组卷面板每点一次题库勾选/切一次模式都重绘并再 `openLayer()` 一次，压进多份同名元素；按一次返回只弹掉一份，于是**面板已经滑走、半透明遮罩还盖在整屏上吃掉所有点击**，看起来像卡死。现在同一元素只算一层。
- **滑杆惯性在真机上过强**：慢慢拖到位再松手，会被甩到别的位置（拖到 200 题落成了 264）。改成速度低于阈值就不带惯性，只有真甩动才投影，且投影幅度封顶。
- **微信入口进来时导入界面整个看不见**：进度条和成功页都写在 `sheet3` 里，但从微信「用其他应用打开」进来时这个面板从没被打开过，导入其实是成功的，用户却什么都看不到。现在 `importStage` 会先把面板建出来。
- **换肤的圆形扩散是错位的**（你实测报回的那条）：降级分支里覆盖层只是一圈描边，`update()` 又和它同时执行，于是颜色先跳完、波浪才后知后觉飘过去。现在改成"新主题底色的圆从触点扩散、盖满整屏才换肤"，见上面「换肤的圆形扩散」。
- **界面占不满整屏**（你实测报回的那条）：底部 96px 是不透明的系统导航栏白条，`.tabs` 正好压在返回键下面——根因是 `env(safe-area-inset-bottom)` 在 WebView 里恒为 0。现在走边到边 + 原生回灌真实 insets，见上面「屏幕适配」。

真机上跑通的链路：黑白灰渲染（浅/深两态）、答错进错题本且再答对不出册、多选不点确认不判分、无答案题不判分也不卡死、组卷多库合池与分题型抽题、批量错峰勾选与曲线删除、题库左滑露出删除/隐藏 + 二次确认、系统返回键逐层回收。

导入用你那份 Storage 题源转出的真 `.docx`（1.44 MB）实测：认出 254 题、可用 252、丢弃 2（缺选项缺答案）、重复 0，落盘 `files/banks/<id>.json`（128 KB），**杀掉进程重开仍然在**；左滑删除后磁盘文件同步清掉、题目数回到 960。

`uiautomator` 驱动不了这台机器的系统文件选择器（DocumentsUI 的列表项 `clickable=false`，点击由 RecyclerView 手势层处理，注入事件被吃掉），所以 SAF 那条只验证到"选择器能正常拉起、MIME 过滤后能看到 docx"，选中之后的处理与微信入口共用同一个 `startImport(uri)`，用 VIEW intent 递真 URI 验的是同一段代码。

## 版本与更新

当前 **v1.0.0**（`versionCode 1` / `versionName 1.0.0`，都在 `app/build.gradle.kts`）。

「我的 → 检查更新」会请求 `https://api.github.com/repos/HagimeLab/GIme/releases/latest`，拿 `tag_name`（会剥掉前缀 `v`）和本机版本按**段做数值比较**（`1.0.10 > 1.0.9`，不能比字符串），有新版就在弹窗里显示版本号和 Release 正文，点「下载更新」用系统 `DownloadManager` 下载，完成后拉起系统安装页。整个链路不需要服务器，也不额外维护一份 `version.json`——版本号只有 Release 的 tag 一个来源，免得两处各说各话。

没给「安装未知应用」授权时下载会装不上，代码会先探测 `canRequestPackageInstalls()`，不通过就直接跳到该 App 的授权设置页并提示回来重点一次。

### 发版步骤

1. 改 `app/build.gradle.kts` 里的 `versionCode`（**每次都要 +1**，Android 靠它判断是不是升级）和 `versionName`。
2. `build.cmd`，产物在 `app/build/outputs/apk/release/app-release.apk`。
3. 在 GitHub 建 Release：tag 用 `v<versionName>`（如 `v1.0.1`），把 `app-release.apk` 作为资产拖上去。App 就是靠这个 tag 认版本的。

### 签名：一定要备份

发布用**固定的 release 密钥**，文件在 `signing/`（`gime-release.jks` + `keystore.properties`），已写进 `.gitignore`，**绝不入库**——私钥一旦公开，任何人都能签发和你同签名的"更新包"。

`debug` 也指向同一把钥匙，否则 debug 装过的手机换成 release 会因签名不同被系统拒绝安装，只能卸载重装、把做题记录一起带走。

**丢了 `signing/` 就等于永远无法给已装用户推送覆盖更新**（签名对不上，系统只允许先卸载）。请把这两个文件单独备份到网盘或移动硬盘。

## 注意

`gradle.properties` 里有 `android.overridePathCheck=true`——因为项目放在中文路径 `D:\desktop\刷题apk`，AGP 默认会拒绝。实测这样能正常构建；如果以后改成报资源错误，把整个目录挪到纯英文路径再构建即可。
